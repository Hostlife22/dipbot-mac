# Вынесенные ветви, глобальные вызовы и Sweep — 2026-09-24

Оригинал не запускался. Анализ выполнялся на Mac: статическое чтение PE и ограниченная эмуляция FLOSS. Лицензия, реальные кошельки, Keychain, RPC и транзакции не использовались. Production-код не менялся.

## Прямые переходы

`tools/branch_closure.py` обходит инструкции по прямым переходам и fallthrough, не следуя вызовам. Для пяти прежних диапазонов добавлены 6525 достижимых инструкций:

| Исходный диапазон | Всего инструкций | За прежними границами |
| --- | ---: | ---: |
| ui_trade_defaults | 6552 | 6102 |
| runtime_reset | 247 | 110 |
| gui_stop | 324 | 125 |
| getattr_default_prefix_only | 81 | 70 |
| load_config_values | 172 | 118 |

Незакрытых прямых целей в этом ограниченном обходе не осталось. Это **не полный граф исключений или вызовов**: не обходятся SEH-таблицы, callee и динамические переходы. `ui_trade_defaults` начинается внутри функции: аргументы на этой точке не установлены, выводы о self из неё не делаются. Прямой хвостовой переход сам по себе не доказывает принадлежности всех инструкций одной исходной функции.

Дополнительно разобраны runtime_reload (180 инструкций, 99 за прежним unwind-диапазоном), runtime_load (337) и secure_settings_load (994). [Данные с хешами и ссылками на имена](BRANCH_CLOSURE_EVIDENCE.json).

## Глобальные lookup и дополнительные помощники

По машинным инструкциям уточнены четыре операции:

- 0x140006c30: поиск слота словаря по имени; содержимое слота читается отдельно. Имя lookup не доказывает конкретного runtime-значения.
- 0x140f02590: кэшированный lookup `reload_runtime_settings`.
- 0x14000d9e0: вызов type call slot с callable, tuple аргументов и kwargs; RDX/R8/R9 на входе соответственно.
- 0x1429083a0: помощник вызова с вектором трёх аргументов; проверяет arity 3 и читает элементы R8+0/+8/+16.

`tools/extended_calls.py` сохранил 62 обращения в ранее выбранных диапазонах. В частности, `self.ui_state_path.write_text` теперь прослежен до вызова tuple/kwargs по 0x140f36d96. В реестре виден lookup write_protected_json и вызов vector3 по 0x140bb9ace. Точный получатель последнего не прошёл все слияния анализатора; содержимое tuple/kwargs и часть vector-аргументов остаются неизвестными и обозначены null.

[Свидетельства помощников и обращений](EXTENDED_CALL_EVIDENCE.json).

`tools/inline_factories.py` нашёл **33 конструкции функций** внутри инициализаторов runtime_config и secure_store. Это дополняет прежний поиск коротких фабрик, который не охватывал inline-конструкции. `reload_runtime_settings` строится по 0x141dc2510 с указателем тела **0x141dc0230**. В этом теле последовательно вызываются `load_runtime_settings.cache_clear()` и `load_runtime_settings()`; это обновление кэша, не доказательство миграции формата. Дальнейший путь ссылается на load_secure_settings, read_protected_json и validate_runtime_settings. Все условия обработки ошибок и fallback не восстановлены.

[Имена, адреса и хеши инициализаторов](GLOBAL_FACTORY_EVIDENCE.json). Конструкция функции не равна доказательству её конечного runtime-присваивания модулю.

## Sweep, завершение, AutoPair

В completion Sweep:

1. Значение result.remaining проходит проверку истинности; нулевая ветвь по 0x1409192e8 ведёт к 0x14091945b.
2. На этой ветви очищаются UI позиции и `_position_open`.
3. Получается необязательный `self.bot.reconcile_external_flat` с fallback None.
4. Проверяется callable; при ложном результате переход по 0x140919661 пропускает вызов, при истинном call0 выполняется по 0x140919673.

Это условие **данного обработчика**. Оно не доказывает фактическую сверку кошелька или корректность формирования remaining выше по стеку. Проверки skipped/failed следуют далее; новое доказательство durable journal не найдено.

Уточнение следующего прохода: [разбор формирования remaining](STATE_ARGUMENT_AUDIT_RU.md) подтвердил добавление метки неизвестного баланса в remaining самого оригинала. Поэтому приведённый ниже Mac-тест не доказывает отличие Windows при неизвестном балансе.

Для Mac добавлен сценарий: первая позиция имеет неизвестный баланс, второй токен продан, remaining пуст, но failed/unknown непусты. Первая позиция и её entry должны сохраниться после чтения Store заново. Более строгая защита Mac сохранена.

Дополненные ветви GUI.stop не раскрыли новый подтверждённый join/await всех вложенных задач. Связи AutoPair из предыдущего прохода остаются актуальны; нового доказательства периодического опроса PENDING нет. Это незакрытые области, а не подтверждённое отсутствие такого поведения.

## FLOSS: проверка объектов

`tools/floss_object_audit.py` получил контексты со свежим исходным снимком для каждого caller и проверил доступность заголовков receiver/name:

- get_attribute: 245 контекстов; во всех недоступен заголовок receiver, во всех недоступен заголовок имени;
- call1: 51 контекст; во всех недоступен заголовок receiver.

Объекты, хуки с фиктивными результатами и строки не подставлялись. **Корректные Python-объекты и инициализация Nuitka не восстановлены.** Даже отображённый заголовок сам по себе не подтвердил бы семантику объекта. Для продолжения требуется отдельная модель инициализации модулей, CPython type slots, объектов функций и импортов Windows. Просто увеличить лимит или принудительно исправить PC недостаточно.

Прежний полный результат восьми помощников остаётся: 426 контекстов, 8 hook restore failures, 0 извлечённых строк. Новый проход проверяет качество объектов в двух помощниках; это не ещё один полный запуск восьми.

## Проверка и воспроизведение

Десять тестов инструментов проходят в изолированном окружении Capstone; четыре новых проверяют обход переходов, отсутствие перехода внутрь call, отчёт о недоступной цели и перенос результата глобального lookup в call0. Python-инструменты компилируются; git diff --check без ошибок. Итог pytest приложения указан в VALIDATION_RU.md. Сборка и GUI не повторялись: production/packaging не менялись.

```bash
python -m tools.branch_closure "$EXE" --output "$OUT/branches.json"
python -m tools.extended_calls "$EXE" --output "$OUT/calls.json"
python -m tools.inline_factories "$EXE" --output "$OUT/globals.json"
python -m unittest discover -s tools/tests -v
# Отдельное окружение flare-floss:
python -m tools.floss_object_audit "$OUT/expanded.viv" --output "$OUT/objects.json"
uv run --frozen pytest -q
```

Остаются: конкретные runtime-получатели методов, полные keyword/vector-значения, граф исключений/вложенных задач, инициализация Python для FLOSS, условия ошибок защищённого хранилища, периодический PENDING. Windows crash/runtime и системный DPAPI не проверены. Полное совпадение с оригиналом не подтверждено.
