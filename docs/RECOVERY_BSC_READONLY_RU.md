# Проверка восстановления через BSC, только чтение

25 сентября 2026, публичный `bsc-dataseed.binance.org`. Ключи пользователя и его
состояние не читались. Для проверки взята публичная транзакция из недавнего блока;
баланс — USDT публичного пула PancakeSwap, не пользовательского кошелька.

- Receipt `0xfa9f628143babf3905adbd472ce654726047ae0ffa52df4b19a48c0627a98580`,
  блок 123931348: status 1, hash блока совпал с каноническим блоком RPC.
- Баланс USDT адреса пула прочитан на том же блоке; hash повторно проверен после чтения.
  Это проверка исторического чтения, а не расчёт выхода конкретной сделки.
- Проверка receipt через Worker обновила тестовую запись до confirmed, оставив блокировку.
- Для искусственной локальной позиции выполнено сравнение с реальным балансом на
  блоке 123931355. Расхождение обнаружено; локальная позиция не изменена.
- Нулевой неизвестный hash запрошен у реального RPC: ошибка, блокировка сохранена.
- Timeout при проверке сети введён искусственно: блокировка сохранена. Это не
  проверка фактического отключения публичного узла.
- RPC ограничен allowlist чтения. Отправленных транзакций: 0.

В приложении добавлена кнопка «Сверить сохранённые позиции с сетью». Все балансы
читаются на одном блоке, hash проверяется до/после. UI показывает номер блока,
записанное количество, полный баланс токена у кошелька и совпадение/расхождение.
Сверка не меняет позиции и не снимает блокировку. Внешние переводы и несколько
позиций в одном токене могут объяснять расхождение: баланс кошелька не равен
обязательно количеству отдельной сделки.

424 офлайн-теста успешно. Собранная .app проверена синтетическими сценариями
открытой позиции, перезапуска, receipts и отображения расхождения. Это дополнение
к реальному read-only RPC-прогону, а не реальное исполнение сделок через UI.

[Машинный отчёт](recovery-bsc/report.json). Повторение:

```bash
uv run --frozen python -m tools.recovery_readonly_check --output /tmp/recovery-bsc.json
```
