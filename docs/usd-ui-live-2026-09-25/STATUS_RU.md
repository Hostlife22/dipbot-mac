# Проверка USD-интерфейса и LIVE-выхода

## PAPER на DOCK

Токен `0xd61e509004ed608b89fd66193e88ae580e8b04dc`, V3/WBNB,
пул `0x68fBDF8107b82094049f0aC2b1814cc0af2fA0De`.
Естественное наблюдение: 600 секунд, без BUY/SELL, ошибок и расхождений UI.
Исходные DIP/отскок/активность не ослаблялись. Архив завершён и проверен;
этот прогон не подтверждает новый автоматический торговый цикл.
[Отчёт](natural.json), [сверка архива](natural-archive.json).

Отдельный контролируемый PAPER BUY→наблюдение позиции→STOP/SELL на реальных
котировках: 26 наблюдений оценки позиции, чистая остановка, нет расхождений
между детализацией USD и журналом, один SELL учтён один раз, после закрытия
оценка открытой позиции исчезла. Чтобы проверить UI при отсутствии Swap,
только в этом контролируемом прогоне min_swaps=0. Это ручной вход,
а не доказательство естественного DIP. [Отчёт](controlled.json),
[открытая позиция](paper-open.png), [закрытие](paper-closed.png).

При ручном BUY без START автоматическая стратегия не опрашивает котировку
выхода: оценка открытой позиции остаётся неизвестной. Для проверки оценки
наблюдение стратегии было явно включено. Устаревание, отсутствующий USD-курс
и смена режима дополнительно проверены локально, без искусственного сбоя
в естественном рыночном прогоне.

## Найдено и исправлено

Строгая сверка выявила разницу 4×10⁻²⁸ USD между детализацией и журналом из-за
порядка Decimal-операций. Видимый результат не отличался. Теперь итог
детализации берётся из того же closed_delta, который уже используется
журналом; торговые расчёты и журнал не менялись. Для средней цены BUY
используется исходная целочисленная сумма обмена, а не восстановление
из cost−fee. [Исходное расхождение](precision-before-fix.json).
Повтор контролируемой проверки на исправленном коде прошёл.
Одна промежуточная попытка была корректно отклонена фильтром: 0 Swap при
минимуме 1; это не ошибка приложения.

Во время STOP строка состояния теперь сохраняет причину RPC-ошибки и
обратный отсчёт следующей попытки, вместо общего сообщения об ожидании.

## LIVE: реальное исполнение с контролируемым сбоем чтения

В прежнем выделенном кошельке и бюджетном журнале выполнен один малый цикл
USDT/WBNB V2, без сделки DOCK: wrap 0,00003 BNB, BUY на 0,00002 WBNB,
STOP→SELL, unwrap остатка. Всего 6 новых подтверждённых транзакций,
включая два approve. Только перед первой котировкой SELL внедрён HTTP 503;
повтор прочитал котировку через резервный PublicNode. Подпись, отправка,
receipt и балансы настоящие. Продажа отправлена один раз, неизвестного
результата не было. Реальный пост-send сетевой сбой этим не проверен.

Суммы сделки в USD совпали с журналом. Остатки выбранных USDT/WBNB нулевые,
позиция удалена, журнал разблокирован, ошибок UI нет.
[Отчёт и новые receipts](live.json), [STOP с повтором](live-retry.png),
[после продажи](live-sold.png).

Консервативный общий резерв расходов вырос с $0,44542568582050 до
$0,51340687567400 из разрешённого $1. Он включает введённый principal и
резерв газа; это не фактический убыток. Возвраты не уменьшают резерв.
Ограничитель теста проверяет $0,90 до подписи, оставляя запас внутри $1.
Исправлен также пересчёт бюджета: прежний резерв USD больше не уменьшается
при снижении BNB/USD; к нему прибавляются новые резервы. Газ шести новых
receipts: 0,0000382632 BNB. Результат самой малой сделки с газом BUY/SELL:
−$0,02388925095528416310; wrap/unwrap учитываются отдельно в журнале газа.
Не следует оценивать прибыльность стратегии по этой технической сделке.
