# Повторный аудит оригинала и macOS-реализации

> Исторический отчёт. Актуальные исправления конвертера, STOP и журнала, а также оставшиеся различия: [PARITY_AUDIT_RU.md](PARITY_AUDIT_RU.md). Ниже описано состояние предыдущего этапа.

Дата: 2026-09-24. Проверена Windows-сборка NRNF DipBot v1.4.14, SHA-256 `0f9da36f8a9f0b9908d69e00a7c7c3501efb8d9823246078063267dababd0f72`. Это статический анализ нативного кода Nuitka и независимая реконструкция. Windows-программа не запускалась; сравнения сделок двух работающих программ не было. Лицензия и кошельки не читались и не изменялись.

## Метод и воспроизведение

Использованы PE exception tables, Capstone, radare2 6.1.0 и собранный r2ghidra 6.1.0. Ghidra дала вспомогательный C-псевдокод, но Python-исходники не восстановлены. Условия проверялись по x64-переходам, аргументам Python-операторов и ссылкам на таблицы констант. Декомпилятор выдаёт предупреждения о переменных; его вывод не принят за точный исходник.

Декодированы потоки `bot` (245 констант), `trader` (536), `pair_profiles` (170), с проверкой конца каждого потока. Запись константы сама по себе не доказывает её использование. Ниже для основных выводов приведены также адреса кода. VA — виртуальный адрес при image base `0x140000000`, а не смещение файла.

```bash
python3 tools/audit_native.py /путь/к/DipBot.exe --output /tmp/native-evidence.json
# Дополнительно: локальные аннотированные фрагменты машинного кода.
uv run --with capstone python tools/audit_native.py /путь/к/DipBot.exe \
  --output /tmp/native-evidence.json --disassembly /tmp/dipbot-disassembly
```

Инструмент принимает только проверенный SHA-256: адреса нельзя переносить на другую версию EXE. В Git находятся выбранные публичные константы, адреса и хеши участков в [NATIVE_AUDIT_EVIDENCE.json](NATIVE_AUDIT_EVIDENCE.json), без полного бинарника или декомпиляции. JSON описывает измеренные данные; интерпретация ветвлений приведена в этом отчёте.

Первичные описания инструментов: [Nuitka constants reader](https://github.com/Nuitka/Nuitka/blob/develop/nuitka/build/static_src/HelpersConstantsBlob.c), [Nuitka DataComposer](https://github.com/Nuitka/Nuitka/blob/develop/nuitka/tools/data_composer/DataComposer.py), [r2ghidra](https://github.com/radareorg/r2ghidra/tree/6.1.0). Декодер проекта написан отдельно и поддерживает только нужный формат этой сборки.

## Подтверждённые расхождения и исправления

| Область | Было в Mac | Установлено в оригинале / изменение |
| --- | --- | --- |
| База DIP — критично | Максимум цены за период | После проверки DIP: любой рост относительно предыдущего наблюдения переносит базу; два снижения также переносят базу. Исправлено |
| Плоская цена | Счётчика не было | Равная цена сохраняет счётчик снижений. Исправлено |
| Разрыв наблюдений — критично | 10 секунд | Строго больше 0,55 с сбрасывает базу в monitoring. Открытая позиция остаётся под TP/SL. Исправлено |
| Пауза чтений | По умолчанию 1 с | 0,100 с V2 / 0,103 с V3. Исправлены значения; дополнительное время RPC по-прежнему существует |
| BUY minOut — критично | Допуск к router quote после комиссии и price impact | Ожидаемое количество из spot-цены снимка; затем допуск. Добавлена эта нижняя граница, которая не ослабляется после approve |
| Dynamic | Значение выше Slippage × 100 запрещено | Допуск ограничивается `max(0, min(99, Slippage − Dynamic/100))`. Исправлено |
| База TP/SL | Средняя фактическая цена исполнения | Чтение цены после receipt BUY. Исправлено; фактическое количество позиции учитывается отдельно |
| База после SELL | Последняя цена до исполнения | Повторное чтение после подтверждения. Исправлено |
| Deadline swap / receipt poll | 90 с / 1 с | 30 с / 0,2 с. Исправлено |
| Converter round-trip | Проверка только при ADD BASE, на условных 0,01 WBNB | Найден лимит 1500 bps и отдельный выбор безопасного маршрута. Добавлена проверка прямого и обратного выхода на фактическую сумму для каждого кандидата |

Адреса, на которых основаны выводы:

- Инициализация gap/poll: `0x14088ca6d–0x14088cb14`; условное присваивание 0,103 для V3 — `0x14088cb05`.
- Проверка разрыва только в monitoring: `0x14089817b`, сравнение gap с max gap — `0x140898371`.
- DIP вычисляется до growth/down-streak: `0x140898aa0–0x140898f80`. Growth: `0x14089af3a–0x14089b0a5`. Сравнение текущей и предыдущей цены LT: `0x14089b135`; равенство уходит в конец итерации через `0x14089b167`. Счётчик >= 2: `0x14089b3a9`; перенос базы: `0x14089b45d`.
- BUY reference: `_read_price` в `0x140890ff6`, присваивание результата coroutine в `entry_price` через `0x1408907ee`.
- TP проверяется перед SL: `0x14089ba36` и `0x14089bc23`. SL ставит флаг завершения после SELL.
- `Trader.buy_min_out_from_snapshot`: `0x141e63dc0–0x141e65576`; деление суммы на quote scale и цену — `0x141e646a6`, `0x141e646e9`; умножение на token scale — `0x141e64712`; преобразование в int — `0x141e6473a`; Dynamic / 100 — `0x141e64865`; вычитание — `0x141e64952`.
- Converter constants: `0x141e840f5–0x141e8413e`: tax buffer 500 bps, maximum slippage 2000 bps, maximum round-trip loss 1500 bps. Полный порядок применения tax buffer ещё не перенесён.

Реконструированная формула BUY:

```text
expected_raw = floor((amount_raw / 10**quote_decimals) / snapshot_price * 10**token_decimals)
guard_pct = clamp(slippage_pct - dynamic / 100, 0, 99)
minimum_raw = floor(expected_raw * (1 - guard_pct / 100))
```

В Mac используется точная целочисленная арифметика. Значение minOut, округлившееся до нуля, отклоняется; оригинал ограничивает результат снизу единицей. Дополнительно сохраняется более строгая из границ снимка и router quote до/после approve. Поэтому это всё ещё не побитовое совпадение расчётов оригинала на Python float/Decimal.

Пример влияния исправлений: при DIP 3% последовательность `100 → 99 → 98` теперь переносит базу на 98, без покупки; `100 → 98,5 → 97` покупает до переноса базы. `100 → 99 → 99,5` переносит базу на 99,5. Наблюдения в этих примерах разделены 0,1 с.

При Slippage 2 и Dynamic 150 весь допуск составляет 0,5% от spot-выхода. Комиссия пула, price impact, движение цены и налог токена должны вместиться в него. Прежняя версия вычитала комиссию/impact до применения допуска и могла пропускать покупки, которые оригинальный порог отвергал бы. При нулевом допуске даже обычная комиссия может сделать BUY неисполнимым; это следствие восстановленной формулы, а не обещание покупки без проскальзывания.

## Существенные оставшиеся отличия

1. **Converter не эквивалентен.** В оригинале найдены `exactInput(bytes path, ...)`, `quoteExactInput` и профили `via_usdt_v3` / `via_eth_v3`. Это подтверждает наличие интерфейса многошагового V3-маршрута, но не доказывает, что каждый маршрут атомарен. У нас конвертация последовательная, допускает смешанные V2/V3 шаги и выбирает лучший котируемый выход. Предыдущий шаг не откатывается при ошибке следующего. Нативный V2 конвертер и точное применение tax buffer 5% не воспроизведены.
2. **SELL minOut намеренно строже.** В оригинальном `_submit_sell` на `0x1408965a1–0x1408965db` передаётся 1 как `min_out_wbnb_raw`. У нас остаётся котировка со Slippage. Выход может отклониться при резком падении, когда оригинал согласился бы почти на любой выход. Ослабление защиты не включено автоматически.
3. **HTTP и скорость.** Mac проверяет chainId, свежесть блока, пул и router, делает дополнительные котировки и approve точной суммы. Оригинал использует иной hot path и подготовку allowance. Интервал 100/103 мс не означает столько же между полученными ценами. При RPC дольше примерно 0,45 с gap-защита часто сбрасывает базу: теперь это видно в журнале. Замеры одновременной работы двух ботов не проводились.
4. **Ошибки RPC.** В оригинальном цикле виден повтор чтения после 0,05 с; у нас ошибка приостанавливает цикл. Неопределённая транзакция сохраняет блокировку и не отправляется повторно. STOP после неизвестного результата требует сверки.
5. **AutoPair / профили / Sweep.** Совпадают 42 публичных адреса, но оригинал имеет профили по router, приоритеты конвертера и fee-настройки. Mac ищет доступные канонические пулы шире. Порядок выбора, кеширование, обновление пары и все ветви Sweep не доказаны эквивалентными. Проверка ADD BASE в Mac остаётся более строгой (10% на 0,01 WBNB), чем общий лимит конвертера 15%.
6. **Учёт кошелька.** Mac продаёт только записанную позицию; полный баланс доступен через отдельные wallet-операции. В оригинале имеются ветви восстановления из live balance, точная область включения ранее купленных токенов требует дальнейшего анализа. Автоматическое включение посторонних остатков не добавлено.
7. **Старые позиции.** Сохранённая позиция предыдущей Mac-версии сохраняет прежний entry до её закрытия. Ретроспективную цену после старого BUY восстановить из текущей цены нельзя.

## Проверка и границы результата

Регрессионные тесты покрывают последовательности цен, равенство, две границы gap, приоритет DIP перед переносом, Dynamic, разные decimals, сохранение snapshot minOut через approve, post-receipt reference и сбой чтения после уже исполненного BUY. Проверяются граница round-trip 15%, журнал до broadcast и блокировка неоднозначного результата. Данные для сценариев синтетические; это тесты реконструкции, не записи исполнения оригинала.

Реальных транзакций, чтения пользовательского Keychain и проверки лицензии не было. Итоги запуска тестов и сборки — в [VALIDATION_RU.md](VALIDATION_RU.md). Основные ошибки торговой стратегии исправлены; утверждать «работает один в один» по имеющимся данным нельзя.
