# Аргументы, состояние и Sweep — 2026-09-24

Статический проход по Windows v1.4.14, без запуска приложения. Адреса привязаны к SHA256 EXE в JSON-свидетельствах. Производственный код Mac в этом проходе не менялся.

## Trader/bot и аргументы

[Аргументный анализ](ARGUMENT_AUDIT_EVIDENCE.json) дополнен обработкой keyword/vector-помощников и копирования константных словарей.

- По 0x140f0c0c0 прослежена конструкция `Trader(self.current_profile, trade_router=self.current_trade_router)`, затем присваивание `self.trader` по 0x140f0c10f.
- По 0x140f550a0 прослежено создание `DipBot` с девятью именованными аргументами: `trader`, `token`, `amount_wbnb`, `dip_pct`, `tp_pct`, `sl_pct`, `slippage_pct`, `dynamic_dip_factor`, `callback`. Восстановлены значения `self.trader` и `self.callback`; остальные значения анализатор оставляет неизвестными. Далее устанавливается атрибут `bot` по 0x140f55101; получатель присваивания прослежен вручную через загрузку self со стека, но потерян консервативным анализатором.
- В пути сохранения UI восстановлены kwargs `ensure_ascii=True`, `indent=2` и `encoding='utf-8'` для `ui_state_path.write_text`. Содержимое позиционных tuple не восстановлено полностью.

Это происхождение объектов на конкретных путях создания. Оно не исключает переопределения глобальных имён или последующего изменения атрибутов и не превращает прежние 91 кандидатную связь в подтверждённый динамический граф.

## Sweep, REMOVE и AutoPair

[Ограниченные native-диапазоны](SWEEP_SEMANTICS_EVIDENCE.json) уточняют предыдущее описание completion:

1. По 0x14209e494 неизвестный финальный баланс (`None`) обходит численное сравнение и направляется в формирование метки remaining.
2. Метка добавляется в список с проверкой дубликатов по 0x14209e7c6.
3. Ветка None по 0x14209e881 также формирует сообщение `final balance could not be verified` в failed.

Таким образом, неизвестный баланс блокирует условие пустого remaining в исследованном пути оригинала. Нельзя считать прежний Mac-тест с пустым remaining и непустым unknown доказательством потери позиции в Windows. Представления различаются: Windows хранит метки в списке remaining, Mac отдельно хранит измеренные остатки и неизвестные токены. Точный численный порог этой ветви пока не установлен независимо.

После REMOVE по 0x140908e60 вызывается `_schedule_autopair(self.token.text())`. Это ещё один подтверждённый событийный источник повторного поиска. Периодический опрос PENDING не доказан.

В `DynamicPairRegistry.remove` удаление записи предшествует `_save`. Нулевой результат вызова по 0x140bc126e ведёт через 0x140bc127f в обработку исключения. Полный путь восстановления записи не разрешён: ни наличие, ни отсутствие rollback этим диапазоном не доказано. Атомарные защиты Mac сохранены.

## Защищённые настройки и завершение

В `secure_settings_load` отсутствующий файл приводит к созданию `SecureStoreError` по 0x141dd07e2 с сообщением `Secure wallet/node setup has not been completed`. Локальная ветвь не возвращает молча defaults. Возможный fallback у вызывающей стороны этим не исключён.

Прослежены дальнейшие обращения к метке `runtime-settings`, полю version и валидатору. Новая версия формата или миграция не подтверждены. Полный граф исключений, косвенных операций хранения и завершения вложенных задач остаётся неполным; новых доказательств аварийного поведения Windows нет.

## FLOSS: частичная модель имён

[Результат эксперимента](FLOSS_NAMES_MODEL_EVIDENCE.json) получен с `tools/floss_names_model.py`:

- Из уже декодированных публичных констант построены заголовки 1220 уникальных ASCII-имён CPython 3.12 x64; обновлены 1975 слотов в памяти временного эмулятора.
- Бандлированная python312.dll отображена исключительно как читаемые данные для адреса экспорта `PyUnicode_Type`. DLL entrypoint, Windows API и оригинальное приложение не запускались.
- Все 245 контекстов get_attribute теперь имеют доступные заголовки имени и его типа. Заголовки receiver во всех 245 контекстах по-прежнему недоступны; в 51 контексте call1 также недоступны.

Это сконструированные входные объекты, а не наблюдение состояния оригинала и не новые строки FLOSS. Модель не выполняет imports, инициализацию типов, модулей, словарей, функций или tstate. Семантическая корректность объектов в Windows runtime не доказана. Число прежних ошибок декодирования этим экспериментом не пересчитано: полного decode-прохода с этой моделью не было.

Из корня репозитория, с установленными зависимостями соответствующих инструментов:

```sh
python -m tools.argument_audit "$EXE" --output docs/ARGUMENT_AUDIT_EVIDENCE.json
python -m tools.sweep_semantics "$EXE" --output docs/SWEEP_SEMANTICS_EVIDENCE.json
python -m tools.floss_names_model "$EXE" "$VIV_WORKSPACE" --output docs/FLOSS_NAMES_MODEL_EVIDENCE.json
python -m unittest discover -s tools/tests -q
uv run --frozen pytest -q
```

EXE — исходный v1.4.14, VIV_WORKSPACE — расширенная 27-функционная workspace из предыдущего прохода. PE/ASM и workspace остаются вне Git. Модель FLOSS требует отдельного окружения FLOSS/Vivisect; native-анализаторы — Capstone/pefile.

Полное runtime-совпадение и системная совместимость DPAPI без Windows не подтверждаются.
