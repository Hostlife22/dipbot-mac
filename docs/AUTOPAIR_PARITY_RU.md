# AutoPair, динамические профили и аварийное восстановление

Дата: 2026-09-24. База изменений: `8228f0a`. Продолжение [статического аудита](STATIC_RECOVERY_AUDIT_RU.md). Оригинал не запускался; RPC, Keychain и пользовательское состояние не использовались. Все проверки ниже выполнялись на временных данных и подставных RPC-ответах.

## Реализованные правила AutoPair

`autopair.py` воспроизводит выбор из `choose_candidate` (`0x140858fd0–0x14085a407`):

1. Пустой список → NOT_FOUND.
2. Если есть ready-кандидаты, рассматриваются только они; иначе рассматриваются все найденные пулы.
3. Группировка по `(router, pair_name)`, внутри группы — максимальный liquidity_score. Равный score не заменяет первого кандидата.
4. Несколько групп → AMBIGUOUS. Одна группа → RESOLVED или PENDING в зависимости от ready.

Дополнительно восстановлен ключ сортировки `_discover_token.<lambda>` (`0x140868980–0x140868ef5`): `(router, pair_name.casefold(), -int(liquidity_score), fee or 0, pool_address.lower())`. Отрицание score — импорт `PyNumber_Negative` в `0x140868ba0`. Теперь одинаковая ликвидность приводит к выбору меньшего fee, затем меньшего адреса в этой сортировке. Это отдельный этап перед choose, а не изменение его строгого сравнения.

Показатель V2 — произведение сырых reserves при положительных резервах, V3 — raw liquidity. Native-свидетельство: диапазон `0x140867430–0x1408676b4`, умножение `0x140867560`. Новые диапазоны и хеши включены в `RECOVERY_EVIDENCE.json`; воспроизведение через `tools.recovery_native` теперь охватывает десять диапазонов.

`Chain.discover_candidates` проверяет канонический адрес, factory, стороны, decimals и fee. Отсутствие ликвидности сохраняется в кандидате, но не разрешает торговлю. Выбранный ready-пул повторно проверяется через обычный `verify_pool`, включая цену. Проверка параметров стратегии также отклоняет смену router без новой проверки.

Каждый поиск сбрасывает прежний выбранный пул и список UI до RPC. При таймауте или STOP частичный результат не выбирается автоматически. PENDING показывается в интерфейсе, повторный AutoPair после появления ликвидности может перейти в RESOLVED.

**Ограничение:** таймер автоматического повторения PENDING оригинала не восстановлен; пока нужен повторный AutoPair. Полный оригинальный resolver, который различает mint / pool / catalog token, не перенесён: Mac сохраняет отдельные AutoPair и CHECK POOL. Multicall-пакетирование не перенесено; задержки discovery отличаются. Эти области не объявляются MATCH.

## Динамические профили

Добавлен Mac-реестр `dynamic_registry`, version=1, с ключом `router:base_address`. Запись содержит name, token_address, trade_router, trade_pool, trade_fee, converter_mode, v3_quote_fee, converter_route, roundtrip_loss_bps, decimals, created_at/updated_at. Семантика полей опирается на `dynamic_pairs[141]`; формат файла собственный.

ADD BASE заново проверяет выбранный торговый пул, котирует конвертер целым путём и получает mode/fee из фактического BUY-пути. Реконструированные правила mode — `converter_settings_from_quote`, `0x140bacbf0–0x140badc32`. Сохранённое предпочтение используется в `LiveTrader.conversion_route` до общих fallback-кандидатов; SELL разворачивает путь и fee. Метаданные не заменяют свежие on-chain проверки перед исполнением.

- Профили V2/V3 одной базы хранятся отдельно и попадают только в соответствующий discovery-каталог.
- Повторный ADD обновляет запись, сохраняя name и created_at.
- Старые symbol→address доступны обоим router до явного ADD BASE; отсутствующие mode/fee не выдумываются. При перепроверке старый alias заменяется зарегистрированным. Это консервативная Mac-миграция, не Windows-миграция.
- REMOVE проверяет остатки и сохранённую позицию указанного кошелька; убирает запись и её alias, сбрасывает текущий выбор. Вторая router-запись остаётся.
- Сохранение/удаление готовит отдельную копию состояния; исключение save восстанавливает прежнее состояние памяти. Реестр не затирает журнал операций.
- Имена CUSTOM формируются из адреса и router с устранением коллизий; алгоритм имён Windows ещё не перенесён.

Порог ADD остаётся Mac-ограничением **0.01 WBNB / 10%**. Первичный поиск конвертера для ещё неизвестной базы сохраняет прежний fallback-каталог; автоматическое обнаружение всех ETH-only баз не подтверждено. Поддержка сохранённого via_eth_v3 проверена, но это не доказательство полного соответствия Windows-процедуры ADD.

## Sweep и восстановление

Sweep выбирает контекст конвертера для каждой динамической базы: текущий router при наличии соответствующей записи, иначе единственный зарегистрированный router. Контекст восстанавливается также при ошибке RPC. Если контекста нет, а предпочтения V2/V3 конфликтуют, конвертер требует явно выбрать router. Это собственная безопасная политика, не доказанная полная копия Windows Sweep.

Каталог known_pools теперь записывается по адресу пула: следующий выбор другого пула того же target не теряет прежний маршрут. Старые записи читаются по значениям и сохраняют совместимость.

Добавлены fault-injection проверки:

| Сбой | Ожидаемый результат |
|---|---|
| Запись hash до broadcast | Отправок нет; операция остаётся на диске; restart блокирует новый begin |
| Запись receipt после принятой отправки | Одна отправка; на диске pending; restart не разрешает повторную покупку |
| Таймаут receipt после принятой отправки | Durable hash сохранён; блокировка остаётся |
| Запись/удаление профиля | Старый реестр в памяти и на диске сохраняется при ошибке до замены файла |
| RPC в предварительном выборе base-маршрута Sweep | begin/send не вызываются; контекст router восстанавливается |
| Исчезновение ликвидности перед ADD BASE | Профиль не записывается |

Проверки ошибок записи — инъекция исключений, не физическое отключение питания. Не все точки падения процесса и не все варианты fsync/replace покрыты. Журнал, minOut, точные allowances и запрет повторения неоднозначной отправки сохранены.

- **156 offline-тестов прошли** (было 117); одно прежнее предупреждение websockets.legacy.

P12 сужен: реализованы выбор/сортировка кандидатов и router-specific предпочтения динамического конвертера. Остаются полный resolver/автообновление PENDING, защищённый Windows registry, полная процедура ADD/REMOVE и каталоги оригинала. P13 сужен за счёт новых проверок Mac; полный Windows crash/restart и Sweep runtime остаются неизвестными. P18 в этом проходе не расширялся. P14, LIVE, reorg/finality и длительная работа не проверялись.

Полное совпадение и готовность к LIVE не заявляются. Commit/push в этом проходе не выполнялись.
