## Исправление текущего прохода

Реальные тесты файловой записи обнаружили расхождение Mac после `os.replace`: ошибка открытия/fsync каталога откатывала память, хотя файл уже содержал новый реестр. Это затрагивало ADD/REMOVE, сохранение предпочтений и общий helper persist.

`Store.save` теперь отличает `SaveAfterReplaceError` от ошибки до замены. Публичный реестр и настройки после такой ошибки сохраняют новое видимое состояние в памяти, а до замены по-прежнему откатываются. Ошибка durability сообщается безопасным фиксированным текстом, без вывода исходного исключения. Журнал LIVE и блокировка неопределённых операций не ослаблены.

Проверены реальные границы file fsync / replace / directory open / directory fsync для ADD, REMOVE и настроек, включая совпадение каталога с повторным чтением файла и отсутствие временных файлов. Это исправление Mac, а не восстановленная гарантия Windows.

## Следующие конкретные доказательства

1. Для Windows rollback: восстановить значения глобального `write_protected_json`, свойства `path`/`_records`, весь error path вызывающей GUI и доказать либо повторную вставку записи, либо отсутствие такого действия при обычных binding. Одного отсутствия строк `_records` недостаточно.
2. Для численных правил: связать каждый arithmetic-helper/округление вложенных converter-методов с типами входов и проверить границы raw units/decimals. Не переносить float или tax buffer в LIVE автоматически.
3. Для Nuitka/FLOSS: восстановить модульные globals, конкретные функции и type slots вместе с tstate. Сконструированный объект с доступным заголовком не считать корректным Python runtime.
4. Для остальных пунктов: трассировать косвенные вызовы и SEH; сопоставление работающего оригинала и системного DPAPI вынесено за текущие ограничения Mac-only.

Повторное увеличение таймаута FLOSS без восстановления состояния не закрывает пункт 7. В этом проходе не добавлялись фиктивные успешные результаты хуков.
