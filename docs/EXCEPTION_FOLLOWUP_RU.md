# Получатели и ветви ошибок — 2026-09-24

Продолжение статического аудита v1.4.14 на Mac. Оригинал, Windows DLL entrypoint, RPC и транзакции не запускались. Производственный код не менялся. Полный граф программы и runtime-паритет не восстановлены.

## Новые разрешённые вызовы

Помощник `0x142912af0` выполняет `_PyType_Lookup` по типу получателя и при наличии дескриптора вызывает его binding. Это специальный поиск метода через тип, а не обычное чтение атрибута экземпляра. Анализатор сохраняет эту операцию отдельно как `get_special_attribute`.

В `DynamicPairRegistry.remove` прослежены:

- `arg[0]._lock.__enter__` по `0x140bc0f8b`;
- `arg[0]._lock.__exit__` по `0x140bc0ff5`;
- вызов сохранённого `__exit__` по `0x140bc13d6` с вектором исключения;
- вызовы того же получателя по `0x140bc1593` и `0x140bc1619` с константным tuple `(None, None, None)`.

Помощник `0x142908ee0` читает три элемента tuple по смещениям 0x18/0x20/0x28. Содержимое указанного публичного tuple подтверждено декодером констант. Вектор исключения анализатор пока оставляет неизвестным; вручную видны загрузки типа, объекта исключения и traceback. JSON `arguments: [null, null, null]` означает неизвестные значения, тогда как отдельное поле `literal_arguments` означает подтверждённые Python None.

Результат `__exit__` проверяется на истинность, что влияет на подавление/продолжение исключения. Поэтому эти вызовы нельзя трактовать как восстановление удалённой записи. Полного доказательства rollback или его отсутствия нет: динамическая реализация контекстного менеджера и вызываемые функции не замкнуты.

## Внешняя обработка ошибок настроек

В `load_runtime_settings` неуспешный результат `load_secure_settings` по `0x141dbff23` переходит в очистку ошибки и затем к нулевому возврату по `0x141dc01b0`. На этой локальной ветви подстановка defaults не обнаружена.

В GUI reload вызов по `0x140f2d401` при ошибке переходит по `0x140f2d40c` в обработчик. Он пропускает успешную последовательность `_recreate_trader_after_settings_change` → `_load_settings_from_config` и формирует сообщение `NODE / GAS reload error: ...`. Это обработка конкретного внешнего пути, а не доказательство отсутствия fallback во всех точках входа. Отката уже изменённого состояния на других ошибках этим не установлено. Новых версий защищённого формата не найдено.

## AutoPair и завершение

Помимо REMOVE, подтверждён вызов `_schedule_autopair(token.text())` по `0x140906185` внутри `_handle_live_pair_result`. Это событийный повторный поиск. Ни этот вызов, ни наличие QTimer в соседних обработчиках не доказывают периодический опрос PENDING.

Повторный прямой обход охватывает девять точек входа, включая GUI.stop, REMOVE, обработчик live-pair и загрузчики настроек. Не осталось неразрешённых прямых переходов в заданных окрестностях. Однако обход не следует по вызовам и SEH-таблицам: это не замкнутый граф исключений и вложенных задач. Все косвенные вызовы отдельно перечислены, включая деструкторы и импортные API; их количество нельзя называть количеством неизвестных методов бота.
