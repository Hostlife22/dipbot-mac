## Продажа TARGET

`_sell_target`, `0x142097550–0x142098884`:

1. Создаёт trader для router/pair выбранного кандидата.
2. Получает quoted/min_out через `_target_min_out`; нулевая котировка вызывает ошибку.
3. Выполняет `ensure_approve_max` (`0x142097ee0`).
4. Вызывает `_simulate_target_sell` (`0x142097f39`).
5. Отправляет `fast_sell_token_wbnb` с deadline_sec=60 (`0x142097f82–0x142097fcc`).
6. Ожидает receipt, проверяет status; revert вызывает RuntimeError.
7. Возвращает результат и закрывает trader; закрытие также есть в ветке исключения.

`_target_min_out`, `0x1420945f0–0x142095fb4`: V2 использует reserves и v2_min_out_from_reserves; V3 — quoteExactInput и min_out_from_quote. Название `wbnb` не означает, что база всегда WBNB: путь использует quote_token_address выбранного профиля.

Симуляция формирует V2 swapExactTokensForTokensSupportingFeeOnTransferTokens либо V3 exactInputSingle и вызывает `.call({'from': address})`. Deadline симуляции — текущее время +60. Это проверка вызова после approve, а не отправка сделки.

**Перенесено:** Sweep Mac симулирует тот же объект SELL-вызова после approve, перед send; deadline=60. Ошибка симуляции не допускает отправки SELL. Обычные BUY/SELL сохраняют прежний режим. Тесты проверяют обе версии router, порядок approve/call/send и отказ симуляции.

**Сохранённые отличия:** Mac использует точный allowance вместо unlimited approve, повторную котировку с сохранением более строгого minOut, проверку фактического изменения баланса и durable-журнал. После ошибки симуляции approve уже мог быть отправлен: журнал не очищается автоматически.

## Конвертация BASE

`_convert_base`, `0x142098890–0x142099f28`, перебирает V2/V3. Подходящим считается router, у которого есть **то же имя профиля и совпадающий token_address**. При пустом списке — ошибка «PAIR profile is no longer installed». Если V2 есть в списке, выбирается V2 (`0x142099267–0x142099297`), иначе первый доступный router. Далее preview_quote_to_bnb → execute_quote_to_bnb → wait → status; trader закрывается и при ошибке.

**Перенесено:** выбор контекста базы в Sweep больше не наследует текущий торговый router. Проверяется имя и адрес в свежем каталоге; приоритет V2, затем V3. Отсутствующий профиль пропускается и попадает в отчёт, остаток проверяется. Исходный контекст trader восстанавливается даже при ошибке. Вызов конвертера по-прежнему заново котирует путь.

Область имён Mac пока глобальная: одинаковый токен может получить разные alias для V2/V3. Приоритет действует только при совпадении выбранного имени, как в проверенном методе; это не означает полного совпадения каталогов Windows.

## Удаление записи

`DynamicPairRegistry.remove`, `0x140bc0c60–0x140bc19b7`: нормализация аргументов, вход в lock, поиск записи, pop, save, выход из lock. В проверенном теле нет RPC, balance-reader или trader. Вместе с предыдущим разбором GUI это снимает предположение, будто оригинальный REMOVE обязательно проверяет все остатки on-chain. Проверки остатков Mac сохранены как явное более строгое ограничение. Неудачный save Mac сохраняет прежний реестр в памяти; полная Windows rollback-семантика отдельно не доказана.

## Что пока не перенесено

Общий Sweep оригинала продолжает работу после исключений внутренних методов. Разобранные методы могут выбросить исключение после отправки, при ожидании receipt или после revert. Поэтому нельзя трактовать любую их ошибку как «ничего не отправлено». Mac сохраняет блокировку после durable begin. Полную модель nonce/журнала оригинального Trader, взаимодействие `_close_trader` с частичным исполнением и восстановление после crash ещё нужно исследовать.

Не подтверждены Windows runtime, LIVE, поведение реальных RPC, reorg/finality и криптографическая совместимость DPAPI. Периодический polling PENDING по-прежнему не найден в проверенных обработчиках.
