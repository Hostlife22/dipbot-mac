# План улучшения DipBot Mac

Работа по запросу пользователя от 25 сентября 2026: законченный этап → проверка →
исправления → commit/push → следующий этап. Численные цели скорости устанавливаются
по измерениям. Успешные синтетические тесты не доказывают прибыльность или LIVE.
Исходный аудит: `RELEASE_FINAL_AUDIT_RU.md`, 425 тестов, 15 минут PAPER.

## Ограничения приёмки

Notarization требует Apple Developer credentials, проверка ARM — соответствующего
Mac/runner. Приватная отправка зависит от провайдера. Доказательство прибыльности
требует независимой выборки; краткий прогон его не заменяет. Эти пункты не объявлять
выполненными из-за наличия кода или документации.

## Этап 1: диагностика и исходные измерения

`telemetry.py`: скользящие 2048 замеров на ряд, максимум 128 рядов, счётчики за
процесс; p50/p95/p99 в миллисекундах. RPC URL, параметры, ответы и кошельки не
сохраняются. RPC ошибки JSON отдельно от транспортных исключений. Кешированный
chainId не считается сетевым запросом. Процентили включают неуспешные попытки.

Обычный запуск сохраняет `diagnostics/session.json`, `fault.log`, `timings.json`
в локальном каталоге приложения. Python ошибки сохраняются без сообщений,
значений переменных и строк исходного кода. Native faulthandler сохраняет стеки.
Маркер незавершённого процесса показывается при следующем запуске; он не доказывает
причину завершения и не изменяет журнал транзакций. SIGKILL не может записать стек.
Статистика пока сохраняется при завершении, поэтому авария может потерять замеры.
Это первый инструмент диагностики; причина старого завершения ещё не установлена.

## Этап 2: проверка входа на сумму

Добавлено поле «Макс. потери BUY→SELL %» (по умолчанию 3%, допустимо 0–20).
Старые настройки получают значение по умолчанию, новое сохраняется отдельно.
Реальный Chain перед входом PAPER/LIVE запрашивает BUY и обратный SELL на одном
блоке, затем повторно сверяет hash блока. Отказ до записи операции даёт паузу 5 с
и ожидание нового DIP; неопределённая отправка никогда не попадает в эту ветвь.

Это консервативный фильтр двух котировок на исходном состоянии: второй расчёт
не применяет изменение резервов от первой сделки. Это не последовательная симуляция,
не налоговый анализ и не гарантия продажи. Газ исключён. После approve рынок может
измениться; существующие minOut и повторная котировка остаются обязательными.
Полный мониторинг ликвидности открытой позиции ещё предстоит.

439 offline тестов прошли. Добавлены граничные uint256/Decimal сценарии, отказ
при смене hash блока, отсутствие intent при отказе LIVE, перенос старых настроек.
UI проверен на синтетическом профиле: [скриншот](improvements/entry-guard.png).

Read-only BSC: factory нашёл V2 USDT/WBNB
`0x16b9a82891338f9bA80E2D6970FddA79D1eb0daE`. Блок 123944101,
сумма 0.0001 WBNB, обе котировки положительные, потери 0.499375386133%.
Сначала ошибочно указанный вручную адрес был отвергнут как адрес без контракта;
успешный результат получен после поиска через factory. Кошелёк и подпись не использовались.

## Этап 3: отдельная оконная стратегия

По умолчанию остаётся legacy. В UI добавлен экспериментальный режим максимума
наблюдавшихся цен за 1–300 секунд и подтверждение отскока 0–20%. Условие входа:
падение от максимума не меньше DIP, отскок от минимума текущего падения не меньше
заданного значения; цена всё ещё находится в зоне DIP. Нулевой отскок разрешает
немедленный сигнал. Это не доказанная доходная стратегия.

Повторное наблюдение одного снимка блока не создаёт новый сигнал в оконном режиме.
Проверки разрыва сохраняются (0.55 с); это ещё не полный новый механизм свежести.
После отказа от входа окно и минимум сбрасываются. UI сохраняет режим, окно и отскок;
подсказка базы показывает причину и возраст. Настройки проверяются до изменений
кошелька или журнала. Максимум хранится в монотонной очереди с защитой размера.

447 тестов прошли; проверены плавное падение, повторные снимки, истечение максимума,
отскок, разрыв, TP/SL и перенос настроек. Реальный Qt UI сохранён и открыт повторно
на временном состоянии: режим window / 45 s / 0.75% восстановился. Скриншот без
кошельков: [оконный режим](improvements/window-strategy.png). LIVE не выполнялся.

## Этап 4: подписка newHeads и ограниченный HTTP fallback

Добавлен необязательный WSS во вкладке RPC; секретный URL хранится только в Keychain
по установленной галочке. Загрузка не подключает сеть. Подписка проверяет chainId,
принимает только свою subscription, хранит последний head, не обновляет время здоровья
на дублях. Переподключение с паузой, ошибки сохраняются только по имени типа.

Worker продолжает получать канонические котировки через HTTP. Новый head может
вызвать чтение раньше; без нового head задержка повторного HTTP ограничена 0.3 с,
при нездоровой подписке действует прежний HTTP polling. Пауза после ошибки котировки
не обходится уведомлениями WS. Пропуск/смена ветви сбрасывает базу входа, позиция
сохраняется. Завершение Worker останавливает подписку. Это первый транспортный этап:
backfill логов и отдельный мониторинг цен во время ожидания receipt ещё предстоят.

456 тестов общего набора прошли; после добавления проверки отсутствия busy-spin
дополнительно прошли 27 целевых тестов (общий набор теперь содержит 457 тестов).
Локальный WebSocket server проверяет handshake, subscribe, reconnect и shutdown.
Временная отдельная .app собрана, bundled smoke и codesign --verify прошли.
[UI без пользовательского состояния](improvements/websocket.png).

Публичный read-only WSS `bsc-rpc.publicnode.com`: 15.02 с, 32 уникальных head,
0 reconnect, последний блок 123944769, поток завершён. Два последовательных
15-секундных чтения V2 USDT/WBNB: HTTP — 98 цен / 35 блоков / 196 RPC;
WS+HTTP — 65 цен / 34 блока / 131 RPC. Медиана одного чтения 152.50 / 152.72 мс.
Это краткое сравнение разных временных отрезков, не доказательство меньшей задержки
торгового сигнала. Отправок транзакций нет.

API: https://websockets.readthedocs.io/en/15.0.1/reference/sync/client.html

## Этап 5: согласованность восстановления

Сверка теперь суммирует позиции по кошельку и токену, делает одно чтение баланса
для группы, проверяет совпадение decimals. Ранее каждая позиция одного токена
ошибочно сравнивалась со всем балансом кошелька. Неизвестные внешние переводы
по-прежнему требуют сверки; отчёт не распределяет их между позициями автоматически.

Журнал различает prepared/submitted/receipt_validated. Prepared не означает,
что отправки не было: авария возможна после broadcast и до сохранения submitted.
Любая такая неопределённость сохраняет latch. Перед подписью проверяются chainId,
nonce, value, gas и gasPrice построенной транзакции. В журнал попадает её публичная
оболочка, без подписи/сырой транзакции/ключа. Keyless receipt review сохраняет газ,
если RPC вернул gasUsed/effectiveGasPrice. Автоматическая замена транзакций ещё не реализована.

465 тестов прошли, включая сбой записи после ACK и до receipt. Два отдельных UI
процесса прошли synthetic position-check / resume: BUY/TP/SL/STOP, ошибка продажи,
перезапуск с блокировкой, расхождение балансов и pending→confirmed без разблокировки.
Ожидаемые искусственные ошибки включены в отчёты; отправок нет.
[Синтетический UI восстановления](improvements/recovery-stages.png).

Дополнительный [read-only замер RPC](improvements/rpc-probe.json): по 15 чтений V2/V3.
Binance: медиана 157.53/159.02 мс; PublicNode: 145.26/147.24 мс;
`bsc-dataseed-public.bnbchain.org` — ConnectionError. Конечные блоки снимались в разное
время, поэтому разницу номеров нельзя считать измерением отставания между узлами.

## Этап 6: UI во время исполнения

BUY/SELL в PAPER и LIVE с реальным Chain запускает отдельный read-only монитор
того же канонического пула. Он не получает ключ, Store или LiveTrader. UI забирает
последний снимок каждые 250 мс, без очереди цен. Ошибка чтения, возраст более 0.55 с,
другой пул или другой режим исключают снимок. Обновление UI не меняет цену сигнала
Worker и не запускает второй исполнитель. Подпись/nonce/receipt остаются последовательными.

Монитор останавливается в finally; текущий сетевой вызов ограничен timeout 2 с,
последующие запросы отменяются. Операция не ждёт длительного завершения мониторинга.
Это обновление отображения при исполнении; параллельного принятия новых торговых
решений во время pending и непрерывного общего мониторинга всех токенов пока нет.

468 общих тестов прошли; после ограничения timeout/cancellation дополнительно
прошли 25 целевых тестов. Проверены независимое обновление, старый снимок, другой
пул, неизменность цены сигнала и отсутствие дубликатов графика.
Read-only BSC: 8.01 с, 22 свежих снимка / 15 блоков, ошибок нет, поток остановлен.
[Синтетический UI](improvements/execution-monitor.png); реальные отправки не выполнялись.

## Этап 7: возраст блока отдельно от времени чтения

При запуске стратегии задаётся лимит возраста блока 1–30 с (новое значение по
умолчанию 5 с). Он применяется к основному RPC, резерву и монитору исполнения.
Старый блок вызывает retryable StaleBlock, не выдаёт новую цену и не снимает
позицию. Прежнее сетевое ограничение до запуска стратегии — 30 с. Разрыв локальных
наблюдений >0.55 с остаётся отдельным правилом. Timestamp имеет секундную точность;
это не измерение доставки события с миллисекундной точностью.

UI показывает номер/возраст блока, время последнего чтения и резервный источник.
Резерв сохраняет валютный контекст BSC для USD-пересчёта. Во время BUY/SELL статус
явно сообщает об исполнении, даже когда монитор показывает новую цену.

Общий набор 468 тестов прошёл; затем 4 новых теста свежести вошли в успешный целевой
набор из 25 тестов. Предел 4 с сохранён и восстановлен двумя реальными Qt окнами
на временном состоянии. [Синтетический UI](improvements/freshness.png).

## Этап 8: архив рынка и причинный stress replay

В UI включаемая запись рынка (по умолчанию включена): отдельный writer, очередь
1024 записи, до 10 MiB на запуск и 200 MiB на каталог. Старые записи не удаляются
автоматически; заполнение/ошибки обозначают неполные данные и не затрагивают
торговый журнал. Файлы 0600, без URL RPC, кошельков, подписей и ключей.
Отдельно записываются цены для отображения, наблюдения стратегии, сигналы и исполнения;
replay предпочитает наблюдения стратегии. Нет footer/есть пропуски — replay отказывается.
[UI записи](improvements/market-recording.png).

Воспроизведение с явными допущениями:

```bash
uv run --frozen python -m tools.replay_market \
  docs/improvements/market-prices-15m.jsonl \
  --output /tmp/replay-result.json --latency .25 --fee-bps 25 \
  --impact-bps 0 --tax-bps 0 --gas-quote 0
```

Это модель фиксированных расходов, не симуляция контрактов: нет depth/MEV/receipt/
nonce/sellability. Gas=0 означает исключённый газ. Даже latency=0 исполняется только
на следующем наблюдении; конец записи не создаёт вымышленный SELL. BUY проверяет
snapshot minOut, TP/SL использует цену сигнала как текущий PAPER. STOP LOSS не
перезапускается автоматически. Неоптимизированные настройки и расходы видны в JSON.

480 тестов прошли; после разделения display/strategy observations дополнительно
прошёл целевой набор. Проверены потери архива, неполный footer, причинность, отложенное
исполнение, minOut, обе комиссии газа и отсутствие автостарта после SL.

Сохранены 5337 реальных публичных цен из финального 15-минутного прогона. Синтетические
ценовые фазы исключены, но остаются искусственный RPC outage и STOP/START; блоки
тогда не записывались. Это один исследованный участок, не независимая валидация.
[Данные](improvements/market-prices-15m.jsonl), [результат](improvements/replay-15m.json).
Legacy: 0 сделок. Window 60 с / без отскока: BUY+SL, результат -0.000000752693105159…
базового актива, около -2.51% от 0.00003 на вход; газ/налог/impact исключены.
Этот результат не обосновывает переключение стратегии по умолчанию на window.

## Этап 9: исторические отметки USD и расходы

Новые LIVE позиции сохраняют курс базы и USD стоимость входа с газом операции
BUY/approve. Каждый receipt сохраняет газ и доступную USD-отметку WBNB; отдельный
реестр газа не ограничен последними 100 операциями history. Закрытие позиции
атомарно с удалением её записи сохраняет расходы SELL и исторический USD-результат.
Идентификатор SELL делает добавление результата идемпотентным. При недостающем курсе,
газе или расхождении проданного количества запись остаётся неполной, не превращается
в нулевые расходы. Некорректные числовые поля газа в receipt сохраняют LIVE latch.

PAPER сохраняет USD стоимость входа/выхода для текущего бумажного контекста, без
газа и налога. USD отметки ориентировочные: DEX Screener, возраст до 90 с при фиксации,
не точная историческая фиатная цена блока. Новый результат не пересчитывается при
последующей смене курса. Footer остаётся только USD, прежнего размера. В RPC-вкладке
есть отчёт «USD-учёт и расходы». [Синтетический footer](improvements/historical-usd.png).

Ограничения: старые сделки не мигрированы в USD; LIVE итог охватывает отслеживаемые
позиции этого кошелька с начала нового учёта. Converter/Sweep/revert gas хранится
отдельно, но распределение этих расходов по позициям ещё не выполнено. Стоимость
покупки использует заданную сумму базового актива; дополнительные списания необычных
base-токенов и внешние переводы требуют отдельной сверки. Это не полный portfolio NAV.

487 тестов прошли. После небольшого исправления подписи рынка при переключении
DEMO→LIVE/PAPER прошли 28 целевых UI/учётных тестов. Проверены истечение курса,
неизменность исторического USD, оба газа, missing и неверные поля receipt, повторная
запись закрытия, дефицит инвентаря. Реальных сделок не было.

## Текущее продолжение

Этапы 1–9 выше — проверенные поставки, не закрытие всех 24 целей таблицы.
Дальше: USD-размер позиции и резерв газа; исполнимая выручка для TP/SL; мониторинг
ликвидности/ранжирование токенов и маршрутов; качественная симуляция; безопасная
обработка зависших транзакций; длительные проверки и новая финальная сборка.
Остаются отдельные работы по независимой валидации, backfill событий, адаптивным
профилям, внешним расходам/портфелю и распространению приложения.

## Этап 10: USD-размер и запас газа

Единица AMOUNT выбирается в UI: база пары или USD. Для USD нужен PAPER/LIVE,
проверенный пул и свежая отметка курса. Перед каждым входом сумма базы вычисляется
заново; отсутствие курса отклоняет вход до журнала/отправки. Базовые и USD суммы
сохраняются в отдельных словарях по router/pair. Смена единицы не превращает
сохранённые 5 USD в 5 WBNB. Настроенный запас газа (0–1 BNB, default 0.0001)
сохраняется на входах/Converter BUY; SELL, Converter SELL и Sweep могут его расходовать.
Это заданный запас, не прогноз достаточности газа и не ограничение накопленного оборота.
USD в AMOUNT не включает газ и не является точной гарантией фиатной стоимости.

Архив стратегии теперь сохраняет FX для наблюдений и запрошенную единицу/сумму.
Replay USD использует только доступный на момент сигнала FX, фиксирует количество
базы на отложенную сделку и отклоняет сигнал при отсутствии FX.

После добавления размера и резерва общий набор: 493 passed / 1 failed — тест
ошибочно требовал строку `.0123` вместо нормализованной `0.0123`. Исправлено сравнение
численного значения. Последующие целевые проверки прошли; полный итог — 495 тестов.
В отдельном UI-сценарии та же ошибка текстового ожидания прервала тест с работающим
QThread; это ошибка тестового скрипта, не самостоятельная авария приложения.
Повтор с корректным cleanup и численными сравнениями подтвердил перезапуск:
5 USD, 0.0123 базы и резерв 0.0002 BNB восстановлены отдельно.
[UI размера](improvements/usd-sizing.png). Реальных сделок нет.

## Этап 11: дополнительные выходы

В UI добавлены необязательные trailing stop, максимальное время позиции и пауза
после выхода. Нули отключают функции; старые TP/SL не меняются. Приоритет:
TP, SL, trailing, время. Trailing отсчитывается от максимальной наблюдавшейся
цены после входа и останавливает автоматическую торговлю, как SL. Временной
выход допускает следующий цикл после паузы; новая база DIP формируется заново.

Время выхода проверяется на свежем наблюдении, поэтому отсутствие RPC может
задержать выход. Это сигнал по spot, не обещание цены исполнения. LIVE хранит
время входа и максимум вместе с позицией; PAPER сохраняет их при повторном
START внутри процесса. Старые LIVE-позиции без времени входа требуют отключить
таймер или закрыть вручную. Пауза сохраняется при START в том же режиме внутри
процесса, но не переносится между запусками приложения.

Проверки: прежние 495 тестов, отдельные границы trailing/таймера/паузы,
приоритет TP/SL, повтор блока, перезапуск стратегии с позицией и перенос
настроек. Offline GUI smoke прошёл. Реальные сделки не выполнялись.

## Этап 12: TP/SL по котировке всей позиции

Добавлен необязательный режим «Котировка продажи позиции». Он сравнивает router
quote всего отслеживаемого количества с сохранённой суммой входа. Quote закреплён
за блоком, hash повторно проверяется. Ошибка чтения не превращается в старую
котировку: позиция сохраняется, действует ограниченный повтор чтения. Если цена
успела устареть за время дополнительного запроса, решение откладывается.

Газ и token tax не включены; это оценка до исполнения, а не гарантированная цена.
Старые позиции без cost_quote требуют прежний режим или ручной SELL.
Линии TP/SL по spot скрыты в новом режиме, процент показан отдельно. Trailing
сохраняет смысл по максимуму spot. Режим по умолчанию не изменён. Replay применяет
свою явно заданную модель расходов, поэтому его quote не является router quote.

509 общих тестов прошли; дополнительные сценарии проверяют отказ RPC без продажи
и отсутствие неверных линий графика. Read-only BSC USDT/WBNB: блок 123949555,
положительная котировка продажи 1 USDT, один замер полного exit_quote 217.02 мс.
Offline GUI smoke прошёл. Подписей и отправок нет.

## Этап 13: адаптивный источник котировок

Необязательная сохраняемая настройка выбирает основной/резервный RPC только для
чтения рынка. История ограничена 32 замерами на источник. Альтернатива пробуется
раз в 30 с; смена предпочтения требует трёх замеров и медианы на 25% ниже.
Ошибки дают паузу 30–120 с; при отказе допускается одна попытка другого узла.
Оба недоступны — торговля ждёт, запросы не накапливаются. RPC транзакций остаётся
основным. Старый блок или конфликт hash не принимается как следующее наблюдение.

Вкладка RPC показывает медианы и ошибки подряд без адресов endpoint. Это локальный
выбор между двумя настроенными узлами, не рейтинг всех провайдеров. Первая
проверка резервного пула входит в замер и может быть медленнее последующих.

516 тестов, GUI smoke и проверка четырёх вкладок в 1180×850 / 940×700 прошли;
горизонтального скролла нет, STOP остаётся в окне. Read-only BSC: 36 котировок
за 6.70 с, ошибок нет, медианы основной/резервный 151.55/149.87 мс. Пробы ускорены
только в диагностике; разницы для переключения недостаточно. Отчёт:
[adaptive-rpc.json](improvements/adaptive-rpc.json). Транзакций нет.

## Этап 15: фильтр активности пула

Необязательный минимум Swap за последние 100 блоков проверяется перед PAPER/LIVE
входом, до transaction intent. Ноль отключает фильтр и сохраняет прежнее поведение.
Проверяются адрес, topic, длина события, диапазон блоков, removed, дубли и hash
конечного блока. Запрос ограничен 100 блоками и 10000 результатами. Ошибка не
считается нулевой активностью. Это не число независимых участников, не USD-объём,
не проверка wash trading, blacklist или honeypot.

Сигнатуры сверены с исходниками PancakeSwap:
[V2](https://github.com/pancakeswap/pancake-swap-core/blob/master/contracts/interfaces/IPancakePair.sol),
[V3](https://github.com/pancakeswap/pancake-v3-contracts/blob/main/projects/v3-core/contracts/interfaces/pool/IPancakeV3PoolEvents.sol).
V3 включает protocolFeesToken0/1: сигнатура Uniswap V3 здесь неверна.
Replay только цен отказывается моделировать включённый фильтр без Swap-данных.

Read-only mainnet: V2 USDT/WBNB — 22 события в блоках 123950287–123950386;
V3 fee500 — 1 событие в 123950341–123950440. Отправок нет.
Первый общий прогон выявил 8 устаревших ожиданий полного словаря defaults;
добавлен выключенный min_swaps=0 и отдельный тест миграции старых настроек.
35 целевых тестов после исправления прошли, GUI smoke прошёл.
