# Ускорение чтения цены и исправление измерений

Реальных сделок в этом проходе нет. Порог разрыва стратегии остаётся 0.55 с.

## Изменения приложения

- BscHTTPProvider кэширует только успешный chainId 56 не более 30 секунд,
  в пределах одного endpoint. Смена endpoint, ошибки RPC и принудительная
  проверка сбрасывают кэш. Ошибочная сеть и ответы eth_call не кэшируются.
- Обычный Chain.check по-прежнему принудительно проверяет сеть: подключение,
  каноническая проверка пула и подготовка отправки используют этот путь.
  Только чтение цены использует периодическую проверку идентификатора.
- Последний блок читается и проверяется на свежесть при каждом чтении цены.
  Цены, резервы и заголовки блоков не переиспользуются из кэша.
- V3 liquidity и slot0 читаются одним Multicall на одном проверенном блоке.
  Ошибка любой части и нулевая ликвидность прекращают чтение.
- Интервал опроса отсчитывается от начала чтения, включает время RPC.
  Запросы остаются последовательными; пропущенные интервалы не накапливаются.

## Измерение отдельных сетевых запросов

`tools.rpc_latency_probe` измеряет HTTPProvider._make_request, поэтому
локальные попадания в кэш chainId не считаются сетевыми запросами. Параметры,
полные URL и секреты не записываются; используются публичные endpoint.
До изменений — 5 чтений каждого router, после — 10, после прогрева проверок.
Это короткие последовательные по времени замеры, а не SLA провайдеров.

| Endpoint | V2 до → после, медиана | V3 до → после, медиана |
|---|---:|---:|
| bsc-dataseed.binance.org | 394 → 169 мс | 613 → 172 мс |
| bsc-rpc.publicnode.com | 341 → 146 мс | 562 → 150 мс |
| bsc-dataseed-public.bnbchain.org | ConnectionError | ConnectionError |

В стационарном цикле теперь два сетевых запроса на цену: блок + состояние.
Периодическая проверка сети добавляет запрос chainId по истечении TTL.
В исходных десяти циклах (V2+V3) было 65 сетевых запросов, включая 40 chainId.
После изменений двадцать циклов потребовали 40 запросов.

Источники: [до](RPC_LATENCY_BEFORE.json), [после](RPC_LATENCY_AFTER.json),
[сверка Multicall и положительных котировок](RPC_OPTIMIZED_INTEGRITY.json).

## Исправление стенда GUI

Установлено отдельным сравнением: QTest.qWait задерживал рабочий Python-поток.
Для восьми чтений на каждом варианте медианы составили 2701 и 149 мс при
замене ожидания на processEvents + time.sleep. Поэтому прежний десятиминутный
GUI-прогон нельзя считать чистым измерением RPC. Новый стенд освобождает GIL,
записывает сетевые вызовы отдельно от вызовов провайдера и задержки цены.
[Сравнение ожиданий](QT_PUMP_COMPARISON.json).

## WebSocket

HTTP даёт медиану 148–168 мс в длительных проверках, однако отдельное чтение
в GUI заняло 600 мс. WebSocket в этом проходе не внедрён: сначала нужно
оценить более короткий интервал GUI и редкие задержки публичного узла.
WebSocket/newHeads остаётся возможным следующим шагом. Для него потребуются контроль свежести, переподключение,
обнаружение пропусков и реорганизаций, без выдачи старого снимка за новый.

## Проверка приложения

- Полный offline-набор: **365 passed**; предупреждение deprecation websockets.
- Исходный и собранный GUI: smoke-test успешно; codesign --verify --deep --strict успешно.
- Двухминутный PAPER на Binance RPC, интервал 0.1 с: **686 котировок**,
  медиана чтения 168.17 мс, максимум 453.8 мс; промежутков между наблюдениями
  больше 0.55 с — **0**. Реальных транзакций — **0**.
  [Результат](RPC_FAST_PAPER.json). Это проверка Worker на живых котировках,
  отдельная от сценария собранного GUI; не гарантия задержек публичного RPC.

Повторить замеры публичных RPC:

```sh
uv run --frozen python -m tools.rpc_latency_probe --samples 10 --output /tmp/rpc-latency.json
```

Повторить десятиминутный сценарий собранного приложения (каталог должен быть новым):

```sh
'dist/DipBot Mac.app/Contents/MacOS/DipBot Mac' \
  --paper-acceptance /tmp/dipbot-paper-new \
  --acceptance-endpoint https://bsc-rpc.publicnode.com \
  --acceptance-seconds 600
```

## Десятиминутный PAPER в собранном .app

PublicNode, Cocoa, интервал 0.5 с, прежний порог 0.55 с:

- 600 секунд, 1194 наблюдения цены; медиана чтения 148.38 мс,
  p95 216.78 мс, максимум 600.23 мс.
- 80 сбросов стратегии по разрыву больше 0.55 с. При интервале 0.5 с
  запас до порога всего 50 мс: колебания времени ответа влияют на промежуток
  между наблюдениями. Успешное завершение сценария не означает отсутствие разрывов.
- STOP/START в середине, пауза при искусственном обрыве RPC,
  повторный запуск после восстановления и чистое закрытие — успешно.
- Реальные сетевые chainId: 24 вместо 3643 логических обращений к провайдеру;
  последний блок продолжал читаться на каждом наблюдении.
- Реальных сделок — 0. Рынок не дал сигналов PAPER BUY/TP/SL,
  поэтому этот прогон не доказывает прохождение полного торгового цикла.
- Единственная ошибка в отчёте — намеренно внедрённый ConnectionError.
