| Ветвь | Вызов сравнения | Поведение |
|---|---|---|
| TARGET balance | 0x14209b1cf | Баланс <= 0 переводит в zero_balance; положительный продолжает обработку |

## Сохранение файла и rollback памяти

Расширен обход `_save` → защищённая сериализация → `_atomic_write_bytes`. Внутри атомарной записи прослежены подготовка каталога, tempfile.mkstemp, fdopen, write, flush, fsync(fileno), выход из контекстного менеджера и replace. В ветви обработки ошибки присутствует удаление временного файла с missing_ok=True. Пути закрытия и исключений включены в прямой обход.

Это подтверждает механизм замены файла через временный файл. **Он не доказывает rollback словаря `_records` после pop.** Состояние файла на диске, реестра в памяти и результат возврата после ошибки — разные части поведения. Нельзя считать весь REMOVE атомарным лишь из-за имени `_atomic_write_bytes` или вызова replace. Вложенные динамические вызовы и SEH не замкнуты; поведение при реальном падении процесса не проверено.

## Восстановленные аргументы

Анализатор теперь распознаёт адрес элементов константного tuple после прибавления 0x18, соответствующего проверенному x64 layout. Значения выдаются отдельно от неизвестных аргументов.

- 0x141dcbce5: `parents=True`, `exist_ok=True` для mkdir.
- 0x141dcce9c: `missing_ok=True` для unlink.
- Внутренняя сериализация: `ensure_ascii=True`, `sort_keys=True`, `separators=(',', ':')`.
- Сериализация внешнего envelope: `sort_keys=True`, `separators=(',', ':')`.

Содержимое позиционных tuple и часть получателей по-прежнему неизвестны. Анализатор не интерпретирует произвольную память как tuple. Тест проверяет, что неверное смещение 0x10 не даёт ложных keyword-значений.
