# Статический аудит и read-only BSC, 2026-09-24

Проверены все пять заявленных направлений без запуска Windows EXE. Найдены и исправлены неверные новые defaults SL/slippage и ошибка распознавания WBNB через RPC. Полная эквивалентность оригиналу не установлена: ниже разделены наблюдаемые правила, изменения и ограничения.

## Метод и воспроизводимость

Исследована сборка v1.4.14, SHA-256 `0f9da36f8a9f0b9908d69e00a7c7c3501efb8d9823246078063267dababd0f72`. Использованы статическое дизассемблирование PE, Capstone и декомпиляция radare2/r2ghidra. Оригинал, лицензия, пользовательские кошельки и Keychain не открывались для исполнения или импорта.

[Свидетельства](FULL_STATIC_EVIDENCE.json) содержат 26 диапазонов native-кода, выбранные публичные константы и кандидаты прямых ссылок из десяти таблиц модулей. Воспроизведение из корня репозитория:

```bash
uv run --frozen python -m tools.full_static_audit /path/to/original.exe --output /tmp/full-static.json
```

Сканер привязан к хешу этой сборки. MOV/LEA-ссылки не являются полным графом вызовов: косвенные вызовы и внутренности всех сторонних библиотек не охвачены. Отсутствие ссылки не доказывает отсутствие поведения. Это реконструкция отдельных правил, не восстановленные исходники автора.

## Восстановление и жизненный цикл Trader

`Trader.__init__` (`0x141e55f60`) загружает runtime settings, создаёт provider/account/contracts, nonce-cache и lock. В просмотренных путях создания, отправки и ожидания receipt прямого сохранения торгового журнала не обнаружено. Константа `open` в bot относится к состоянию позиции, а не сама по себе к открытию файла.

| Хранилище | Назначение и наблюдаемые операции |
| --- | --- |
| `secure_vault.dat` | Защищённые runtime credentials/settings; envelope `runtime-settings`, версия 1 |
| `ui_state.json` | Публичные параметры торговли, выбранные router/pair, суммы пар, окно |
| Dynamic registry | Защищённый JSON, kind/version, список `pairs`, ключ router + token |
| Wallet registry | Реестр токенов по кошелькам; ранее разобранная атомарная замена файла |

Bootstrap вызывает проверку/загрузку/сохранение secure settings. Runtime settings кешируются (`maxsize=1`); save очищает кеш и загружает настройки заново, reset удаляет secure settings и очищает кеш. Это не означает удаления UI state.

`_recreate_trader_after_settings_change` (`0x140921950`) пересоздаёт Trader, обновляет реестр кошелька, сбрасывает held pairs и планирует обновление holdings. В рассмотренных путях не обнаружен отдельный durable close/checkpoint протокол. Поведение завершения процесса и скрытых обработчиков этим не доказано.

Mac сохраняет собственный журнал **до отправки**, nonce/receipt-проверки и блокировку при неоднозначном результате. Они не заменены предположением о Windows. Фактическое восстановление оригинала после аварии между отправкой, receipt и сохранением остаётся UNKNOWN.

## Sweep

Повторно разобраны `run` (`0x142099f30`) и `execute_quote_to_bnb` (`0x141e7e6c0`). Во внешнем проходе каждый перечисленный target/base обрабатывается один раз. Явного цикла «до нуля», счётчика повторов или положительного dust-порога в этих ветвях не найдено. Проверка `zero_balance` относится к нулю raw balance; положительный остаток может дойти до котировки и завершиться ошибкой.

Ошибка предварительного чтения/котировки приводит к failed с продолжением; отсутствие подходящего однозначного маршрута — к skipped. Итоговый остаток и невозможность прочитать баланс должны различаться. Добавление в `tx_hashes` после возврата внутреннего исполнения не является журналом перед отправкой: исключение ожидания может произойти раньше.

Добавлены синтетические проверки: баланс 1 raw обрабатывается один раз и остаётся в отчёте при остатке; timeout предварительной котировки не повторяется, не начинает транзакцию и сохраняет позицию. Ранее проверенные частичные ошибки, fresh routes, approve/simulation/deadline и неопределённые receipts остаются покрыты тестами.

Это не доказывает отсутствие повторов внутри provider или скрытых ветвей. Mac намеренно останавливает дальнейшие отправки при неопределённой транзакции; перенос Windows catch/continue без durable recovery не выполнен.

## AutoPair

`_catalog_matches` (`0x140862160`) и `resolve` (`0x140868f00`) распознают известный базовый актив как `PROFILE_TOKEN` / `CATALOG_TOKEN`, без выбранного пула. В GUI (`0x14090f944`) сообщение предлагает выбрать PAIR вручную. Предположение прежних отчётов о недостающем автоматическом открытии/добавлении такого профиля уточнено: просмотренная ветвь этого не делает. Исправлены тип результата и пояснение Mac.

Подтверждены single-shot debounce 220 мс, generation/selection epoch, dirty/inflight и запуск worker. Просмотрены обработчики событий, смена router/pair, пересоздание Trader и прямые timer-ссылки. Position/balance-события планируют обновление holdings; это не доказательство повторного AutoPair. Повторный поиск связан с вводом, сменой рынка, ADD/REMOVE. Подтверждения периодического опроса PENDING в просмотренных ветвях нет; добавлять такой таймер как «точное поведение оригинала» оснований нет.

Реальная RPC-проверка выявила отдельный дефект Mac: WBNB на отсутствующие pool selectors может вернуть успешный пустой ответ. Теперь только необязательные `factory/token0/token1` допускают empty return и переход к распознаванию ERC-20. Обязательные чтения и непустые повреждённые ответы по-прежнему завершаются ошибкой. Это исправление сетевой совместимости Mac, а не утверждение о точной обработке empty return оригиналом.

## Профили и converter

`_key` (`0x140bb5430`) нормализует router через strip/upper, адрес — checksum/lower; область ключа включает V2/V3. `_unique_name` (`0x140bbbcd0`) использует имена в области router, очищенный uppercase symbol длиной до 16, адресный и числовой суффиксы при коллизии. Глобально уникальные Mac aliases остаются отличием.

Загрузка проверяет envelope kind/version и список pairs, пропускает отдельные некорректные записи, фильтрует конфликты с встроенными токенами. Mac сохраняет более строгий отказ при повреждённом реестре; автоматическая миграция реального защищённого реестра не выполнялась.

Уточнён `_converter_slippage_bps` (`0x141e76010`) и выбор безопасного маршрута:

```text
bps = int(round(float(slippage_pct) * 100))
допустимо 0 <= bps <= 2000
tax_buffer = 500 для V2, 0 для V3
minOut = max(1, expected * (10000 - min(9500, bps + tax_buffer)) // 10000)
```

Например, expected=10000 и slippage=2% дают V2 minOut=9300, V3=9800. Порог round-trip в native выражен целыми bps; Mac проверяет точные 15%. Модель в `tools/native_models.py` и тесты фиксируют native-округление, tax buffer и нижнюю границу 1 raw. **LIVE Mac не ослаблен дополнительным tax buffer**: Decimal и более строгие minOut сохранены. Эти отличия исключают заявление о полном совпадении исполнения.

## Настройки и защищённые форматы

По вызовам конструктора UI (`0x140f144a0–0x140f14b90`) установлены defaults:

| Параметр | Значение |
| --- | --- |
| AMOUNT | 0.02 |
| DIP | 3 |
| TP | 2 |
| SL | 2 |
| SLIPPAGE | 3 |
| DYNAMIC | 150 |

В Mac исправлены SL 5→2 и slippage 2→3 для новых настроек; сохранённые значения не перезаписываются. Соответствующая default BUY tolerance стала 1.5%. Старые тестовые векторы с SL=5 теперь задают этот параметр явно. Значение setup gas `1.0` найдено как константа bootstrap; это не полная трассировка всех gas-defaults, Mac gas 0.1 не менялся.

Публичный UI JSON хранит суммы по ключу `ROUTER:pair`, с fallback на legacy `amount_wbnb`, выбор router/pair и торговые поля. Проверены приоритет суммы пары и восстановление сохранённых параметров. Геометрия Windows-окна не переносится. Не обнаруженные исторические версии/миграции не объявлены поддержанными.

Добавлен конвертер **явно указанного публичного** UI JSON:

```bash
uv run --frozen python -m tools.migrate_windows_ui /path/to/ui_state.json --output /tmp/mac-preferences.json
```

Он создаёт новый файл нормализованных preferences, отбирает разрешённые поля, не переносит credentials, отклоняет vault/envelope и не перезаписывает существующий output. Это отдельный результат для проверки; он не устанавливается автоматически в состояние приложения. Синтетические тесты проверяют эти ограничения.

`_entropy_for_purpose` (`0x141dc4550`) выбирает префикс по purpose, добавляет purpose и кодирует UTF-8. Полученная entropy участвует в DPAPI protect/unprotect. Разделение purpose проверено на искусственных префиксах/данных. В native есть отдельная test-mode ветвь; она не использовалась для обхода защиты или миграции. Синтетический envelope/codec не доказывает криптографическую совместимость DPAPI и доступ к данным другого Windows-пользователя. Лицензионные authority/clock данные вне области переноса.

## Проверка реальной BSC без транзакций

[Результат RPC](READ_ONLY_RPC_EVIDENCE.json): 2026-09-24 13:49 UTC, discovery block 123767739, пять кандидатов, подтверждение V2/V3 пулов WBNB/USDT, Multicall, котировки BUY/SELL и распознавание CATALOG_TOKEN WBNB. Discovery привязан к блоку; дальнейшие проверки и котировки сделаны отдельными вызовами и не являются единым snapshot.

Два dataseed endpoint отказали в соединении; успешен `bsc.nodereal.io` из [документации BNB Chain](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/).

```bash
uv run --frozen python -m tools.read_only_probe --endpoint https://bsc.nodereal.io --output /tmp/bsc-read-only.json
```

Транспорт разрешает только `eth_chainId`, `eth_getBlockByNumber`, `eth_getCode`, `eth_call`; остальные методы отклоняются до отправки. Подписания, пользовательского кошелька и отправки транзакций в этом probe нет. Проверка подтверждает эти пути Mac на сети в указанный момент, не LIVE торговлю и не совпадение с Windows.

## Проверки и оставшиеся границы

245 тестов прошли; source offscreen smoke, сборка Intel x86_64, Cocoa smoke собранной `.app` и codesign verify завершились с кодом 0. Полная фиксация проверок — [VALIDATION_RU.md](VALIDATION_RU.md).

Без исполнения оригинала остаются неподтверждёнными фактические тайминги/сетевые повторы, crash recovery, поведение защищённых данных в Windows-контексте и совпадение торговых результатов. Статический разбор можно расширять на косвенные вызовы и дополнительные функции; выполненный проход не доказывает исчерпывающего покрытия бинарника. Намеренные различия Mac: durable journal и uncertain latch, строгие Decimal/minOut без V2 tax buffer, строгая загрузка реестра и глобальные aliases.
