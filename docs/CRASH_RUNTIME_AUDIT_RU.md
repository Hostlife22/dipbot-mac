# Crash recovery, runtime dispatch и DPAPI

Дата: 2026-09-24. Продолжение [статического аудита](FULL_STATIC_AUDIT_RU.md), база `6309fc8`. Оригинальный бот не запускался. Изменены тесты, инструменты аудита и документация; торговая логика и защиты Mac не ослаблены.

## Аварийное восстановление Mac

Новые проверки в `tests/test_crash_boundaries.py` используют временные файлы, случайный нефинансируемый ключ и подставной RPC. Реальных запросов/транзакций нет.

| Точка сбоя | Проверенный результат после перезапуска |
| --- | --- |
| SIGKILL перед fsync временного файла с hash | Старый JSON читается; намерение операции осталось, отправок нет |
| SIGKILL перед atomic replace | Старый JSON читается; операция блокирует новый begin |
| SIGKILL после replace, перед fsync каталога | В условиях завершения процесса виден новый JSON с pending hash; новый begin заблокирован |
| Ошибка fsync файла / replace | Передача в RPC не вызывается, операция сохранена, временный файл убран |
| Ошибка fsync каталога | Передача в RPC не вызывается; новый файл может уже содержать hash, блокировка сохраняется |
| Потерянный ответ send → перезапуск → обрыв RPC при reconcile | Pending остаётся на диске; повторной отправки нет |
| Возобновление reconcile после обрыва, receipt success/revert | Статус обновляется, блокировка остаётся до проверки балансов |

SIGKILL отправляет родительский процесс после подтверждения дочерним процессом точной точки остановки. Это дополнение к прежним `os._exit`-тестам на границах intent/broadcast/receipt/accounting. Сбой питания/контроллера диска не моделируется: особенно нельзя переносить результат до fsync каталога на внезапное отключение питания.

В этих сценариях дефекта production-кода не обнаружено. Тесты подтверждают ограниченный набор инвариантов Mac, а не аварийное поведение Windows.

## Продолжение статического разбора

[Свидетельства семи диапазонов](RUNTIME_STATIC_EVIDENCE.json) воспроизводятся инструментом:

```bash
uv run --frozen python -m tools.runtime_native /path/to/original.exe --output /tmp/runtime-static.json
```

Для `--disassembly /tmp/runtime-asm` дополнительно нужен Capstone. Проверка хеша допускает только ранее исследованный EXE.

| Обработчик | Наблюдаемый путь |
| --- | --- |
| `GUI.closeEvent`, `0x140f37a90` | Меняет balance generation, останавливает balance timer, вызывает `_save_ui_state`, затем базовый closeEvent |
| `CommercialGUI.closeEvent`, `0x140922010` | Меняет holdings/live-pair generation, останавливает AutoPair timer, делегирует базовому closeEvent |
| `GUI.stop_bot`, `0x140f56f10` | Проверяет bot, вызывает stop; UI использует running, STOPPING и сообщение Stop command sent |
| `GUI.handle_event`, `0x140f3b270` | Диспетчеризация log/price/base_price/dip/state; stopped меняет доступность элементов, остальные состояния включают pending_buy/pending_sell/stopping |
| `_handle_autopair_error`, `0x14090fd90` | Проверяет generation; актуальная ошибка очищает inflight/result, устанавливает ERROR и выводит предложение проверить RPC или выбрать PAIR вручную |
| `_handle_wallet_sweep_error`, `0x14091a140` | Вызывает `_finish_wallet_sweep_ui`, пишет WALLET SWEEP ERROR |
| `_close_trader`, `0x142093c20` | Динамически получает атрибут close с default None, проверяет callable, вызывает найденный callable |

Уточнены косвенные вызовы: например, в GUI.closeEvent `0x140f37c47` загружает имя stop, `0x140f37c4e` вызывает диспетчер атрибута; `0x140f37c9f/0x140f37ca6` аналогично вызывают `_save_ui_state`. Последующий `call rdx` в `0x140f37cca` следует за уменьшением reference count и загрузкой слота типа `+0x30`: его нельзя автоматически считать ещё одним вызовом сохранения или close. Разбор учитывает этот шаблон служебного освобождения Python-объектов.

Наличие необязательного callable close не доказывает наличие метода у каждого экземпляра Trader и не раскрывает все возможные runtime-подстановки. В перечисленных обработчиках не найден отдельный commit торгового журнала, но отсутствие полного графа косвенных вызовов не позволяет заявить, что его нигде нет. Фактическое ожидание потоков/сетевых ответов при закрытии оригинала остаётся неподтверждённым.

## Сравнительные сценарии защиты

`tests/test_protection_comparison.py` сравнивает production `minimum_out` Mac с ранее восстановленной моделью Windows converter, не с исполняемым Windows-ботом.

| Сценарий | Windows-модель | Mac |
| --- | --- | --- |
| expected 10000, slippage 2%, V2 | minOut 9300, включая tax buffer 500 bps | minOut 9800 |
| Те же значения, V3 | 9800 | 9800 |
| V3, 0.005%, expected 10000 | Округление bps до 0 → 10000 | Точное значение → 9999 |
| V3, 0.015%, expected 10000 | 9998 | 9998 |
| V2, 20%, expected 10000 | 7500 | 8000 |
| expected 1 raw, 20% | Clamp до 1 raw | Отказ при округлении выхода до нуля |
| V3, 20.004% | Округляется до допустимых 2000 bps | Отклоняется как >20% |
| Потеря ответа отправки | Полный runtime-результат UNKNOWN | Сохранённый hash, без повторной отправки, ручная сверка |

Проверен также большой integer amount `10**24`. Mac не всегда даёт численно больший minOut: точная десятичная арифметика и округление native bps расходятся в обе стороны на границах. V2 buffer намеренно не добавлен в LIVE. Неопределённое Windows-поведение не подменяется выдуманной эталонной моделью.

## Отдельная DPAPI-проверка для Windows

Подготовлен `tools/windows_dpapi_probe.py`. Он использует только стандартную библиотеку Python и системный Windows PowerShell/.NET. Выполнение из корня скопированного репозитория на Windows с Python:

```powershell
python -m tools.windows_dpapi_probe
```

Инструмент создаёт искусственный JSON, упаковывает его восстановленным envelope codec, шифрует и расшифровывает в отдельных процессах PowerShell, проверяет отказ при неверной entropy и изменённом ciphertext. Используется публичный восстановленный prefix и purpose `runtime-settings`, область CurrentUser. DPAPI через ProtectedData описан в [документации Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata?view=netframework-4.8).

Произвольные файлы/лицензии/кошельки инструмент не принимает, защищённые данные не выводит и не сохраняет. JSON передаётся через stdin, без интерполяции в PowerShell-код. Отчёт содержит только результаты синтетических проверок. На Mac инструмент явно завершается с NOT RUN; отказ до запуска subprocess покрыт тестом.

**Системная DPAPI-проверка здесь не выполнена: доступная среда — macOS.** Даже успешный будущий запуск подтвердит взаимодействие codec с DPAPI в текущем Windows-контексте, но не совместимость с реальным файлом оригинала, другим пользователем или историческими версиями. Для этого нужны отдельные разрешённые фикстуры и соответствующий Windows-контекст.

## Результат и ограничения

Полный набор: **262 passed**, 12.06 с; одно прежнее предупреждение websockets.legacy. Source offscreen smoke пройден. Production-код и упаковка не менялись; сборка приложения из предыдущего прохода не пересобиралась.

Закрыты дополнительные проверяемые сценарии восстановления и различий арифметики; расширена карта обработчиков. Не закрыты runtime parity, реальные аварии Windows, совместимость реальных DPAPI-файлов и исчерпывающий граф всех косвенных вызовов. Commit/push этого прохода не выполнялись.
