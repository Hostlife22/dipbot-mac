# Открытые позиции: проверка собранной .app

25 сентября 2026. Проверка выполняется с искусственными ценами, котировками и
локальным хранилищем. Конструктор сетевого клиента, Keychain и отправка LIVE
заблокированы. Это проверка интерфейса и управления позицией, не исполнения на BSC.

## Проверенные сценарии

- START → цена 100 → 96: автоматический DIP BUY, количество TARGET с округлением
  до raw units, ENTRY 96, TP 97,92, SL 94,08.
- Цена 99: автоматический TAKE_PROFIT. Расчёт PAPER P&L и его показ в footer
  совпадают с искусственной котировкой на размер позиции.
- Новая открытая позиция → ошибка чтения: WAIT RPC, количество TARGET сохранено,
  UI сообщает о недоступности TP/SL. После восстановления при цене 93 происходит
  STOP_LOSS без повторной покупки; стратегия останавливается.
- STOP при открытой позиции: позиция закрывается.
- Ошибка котировки продажи во время STOP: стратегия останавливается, позиция и
  ENTRY сохраняются, SELL POSITION остаётся доступной. После восстановления
  ручная продажа закрывает позицию и возвращает статус IDLE.
- Второй процесс .app читает подготовленную синтетическую позицию и pending-операцию
  из файла: после подключения тестового объекта кошелька отображаются позиция и
  LOCKED, START/BUY/SELL недоступны, Worker запрещает наблюдение с торговыми действиями.
  Это загрузка фикстуры новым процессом, а не аварийное завершение настоящей сделки.

Дополнительно полный pytest включает принудительное завершение дочернего Python-
процесса на границах intent, broadcast, receipt и accounting. Fake provider и
случайный неподкреплённый ключ исключают настоящую отправку. Проверяется сохранение
журнала и запрет повторной операции после перезапуска.

## Найденное и исправленное

После неудачного STOP успешная ручная продажа оставляла старый статус ERROR.
Теперь успешное завершение продажи очищает причину ошибки; повторная ошибка
продажи её не очищает. При открытой позиции UI предлагает повторить SELL POSITION
или STOP после устранения причины, вместо общей подсказки о START.

## Результаты и ограничения

417 тестов успешно. В отчёте основной UI-проверки одна ожидаемая ошибка TimeoutError —
она намеренно вызвана при продаже по STOP. Неожиданных ошибок не обнаружено.
Оба запуска собранного приложения имеют `frozen: true`, `passed: true`.
Проверки запуска и подписи .app также успешны.

PAPER не сохраняет виртуальную позицию между процессами. Восстановление выше
относится к локальным данным LIVE; Keychain, реальные receipts, сеть и реальное
исполнение этим сценарием не проверяются. Нулевые комиссии искусственной котировки
и полученный P&L не являются прогнозом торговли.

## Повторение

Первый запуск требует нового каталога; второй использует подготовленную фикстуру:

```bash
'dist/DipBot Mac.app/Contents/MacOS/DipBot Mac' --position-check /tmp/dipbot-position-new
'dist/DipBot Mac.app/Contents/MacOS/DipBot Mac' --position-check /tmp/dipbot-position-new --position-check-resume
```
