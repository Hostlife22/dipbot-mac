# DipBot Mac 0.1

[Главная](README.md) · [Архитектура](docs/ARCHITECTURE_RU.md) · [Разработка](CONTRIBUTING.md)

Независимый аналог NRNF DipBot для macOS с исходным кодом. Создан по документации и статическому разбору Windows-сборки v1.4.14. Это экспериментальная реализация, а не восстановленный исходный проект автора. Совпадение торговых сигналов с оригиналом не установлено.

## Последний аудит

[Статический разбор и проверки BSC](docs/FULL_STATIC_AUDIT_RU.md) описывают восстановленные правила и оставшиеся различия. Новые defaults: AMOUNT 0.02, DIP 3, TP 2, SL 2, SLIPPAGE 3, DYNAMIC 150; сохранённые параметры сохраняют свои значения. В отчёте приведены команды отдельного преобразования публичного Windows UI JSON и read-only RPC-проверки. Преобразованный JSON автоматически в приложение не импортируется.

## Запуск

Если приложение уже собрано, откройте `dist/DipBot Mac.app` или дважды нажмите `START_MAC.command`. После клонирования сначала установите зависимости командами ниже; готовые бинарники в Git не хранятся.
Первоначальная локальная `.app` проверена на **Intel x86_64**, macOS 26.6.2. Apple Silicon нативно требует отдельной сборки в arm64-окружении. Приложение подписывается ad-hoc, без Developer ID и нотарификации Apple.

Из терминала:

```bash
git clone https://github.com/Hostlife22/dipbot-mac.git
cd dipbot-mac
uv sync --frozen --python 3.12
uv run --frozen python launcher.py
```

Сначала можно нажать **START BOT** в режиме **DEMO**. Он работает без RPC, кошелька и доступа к сети.

## Режимы

| Режим | Цена | Исполнение |
| --- | --- | --- |
| DEMO | Локальная синусоидальная модель | Виртуальные сделки |
| PAPER | Настоящие резервы V2 / slot0 V3 через BSC RPC | Виртуальные сделки |
| LIVE | Настоящий рынок BSC | Реальные подписанные транзакции |

PAPER использует router quotes на размер виртуальной сделки: комиссии пула и price impact включены, slippage не списывается как фиксированная комиссия. Газ, token tax и задержка включения не моделируются. DEMO/REPLAY без router сохраняют стресс-модель проскальзывания. PAPER P&L не является прогнозом результата LIVE. При автоматическом отказе PAPER BUY по minOut вход пропускается: пауза 5 секунд, новая база по свежей цене и ожидание нового DIP. Неопределённые LIVE-операции сохраняют блокировку. [Проверки восстановления](docs/ENTRY_RECOVERY_RU.md). [Подробности восстановления RPC и P&L](docs/RISK_PAPER_IMPROVEMENTS_RU.md).

## Настройка BSC и LIVE

1. Во вкладке **RPC и кошелёк** укажите BSC HTTPS RPC, нажмите **Подключить**. Проверяется chainId 56 и свежесть блока.
2. Для просмотра балансов достаточно публичного адреса. Для LIVE введите private key **отдельного** кошелька и нажмите **VERIFY WALLET AND SAVE · Keychain**. Поле очищается, ключ сохраняется только в macOS Keychain.
3. Укажите GAS GWEI. Лимит газа — 0.005 BNB на одну транзакцию. Накопительного бюджета оборота нет: возврат средств позволяет продолжать торговлю без сброса счётчика. Размер покупки задаётся AMOUNT; проверка доступного баланса сохраняется.
4. Во вкладке **Торговля** задайте TOKEN ADDRESS. Выберите PAIR и ROUTER, нажмите **AutoPair**. `ALL` ищет среди всех встроенных и пользовательских баз, что может быть медленно.
5. Если найден один ликвидный пул, он выбирается автоматически. Если несколько — выберите точный маршрут и нажмите **Выбрать**. Если адрес пула уже известен, используйте POOL ADDRESS и **CHECK POOL**.
6. **Единица AMOUNT**: базовый ERC-20 актив выбранного пула или USD. USD пересчитывается перед каждым входом по свежему ориентировочному курсу; без курса вход пропускается. Суммы USD и базы сохраняются отдельно по парам. Для WBNB сначала оберните BNB через **BUY BASE**. Резерв нативного BNB задаётся отдельно в RPC-вкладке; при выходе SELL/Sweep его можно расходовать, накопительного бюджета оборота нет.
7. Настройте DIP, TP, STOP LOSS, SLIPPAGE и DYNAMIC. Выберите LIVE. START, ручной BUY, Converter и Sweep показывают подтверждение с адресами перед реальным исполнением.

24 сентября 2026 выполнены разрешённые LIVE-тесты approve, BUY/SELL V2/V3, wrap/unwrap, Converter и Sweep на малых суммах. Найден и исправлен дефект учёта позиции при продаже через базовый конвертер. Это ограниченная проверка, не подтверждение всех токенов и сценариев; [результаты и ограничения](docs/LIVE_ACCEPTANCE_RU.md). V3 не предназначен для fee-on-transfer токенов.

## Торговые правила этой реализации

- По умолчанию используется режим совместимости: BUY проверяется при падении от базы на DIP процентов. Затем база переносится при росте относительно предыдущей цены или после двух снижений; равная цена сохраняет счётчик.
- Экспериментальный оконный режим: максимум наблюдавшихся цен за 1–300 с и необязательное подтверждение отскока. Он не доказал преимущество по доходности; [воспроизводимый отрицательный пример](docs/improvements/replay-15m.json).
- Разрыв наблюдений строго больше 0,55 с сбрасывает базу входа. TP/SL открытой позиции продолжают проверяться.
- После подтверждения BUY цена пула становится базой TP/SL; реально полученное количество учитывается отдельно. После TP бот продолжает работу, после SL останавливается. После SELL база обновляется новой ценой.
- BUY-допуск: `max(0, min(99, SLIPPAGE − DYNAMIC / 100))`. Нижняя граница выхода рассчитывается из цены снимка **до** комиссий и price impact. Дополнительные router quotes могут только усилить границу; после approve она не ослабляется. Нулевой допуск может сделать покупку неисполнимой из-за комиссии пула.
- SELL POSITION продаёт только учтённую позицию. SELL сохраняет minOut по котировке и Slippage, в отличие от найденного в оригинале minOut=1.
- STOP ждёт текущую отправку и receipt, после чего закрывает учтённую позицию. Неизвестный результат отправки требует сверки.
- Временная ошибка чтения котировки запускает повтор с паузой до 5 с; позиция сохраняется. Ошибка исполнения останавливает цикл; неопределённая отправка блокирует LIVE до сверки.
- Возраст блока контролируется отдельно от интервала чтения: по умолчанию 5 с при запуске стратегии, настраивается в дополнительных параметрах.
- Перед входом проверяются котировки BUY и обратного SELL на одном блоке. Предел потерь по умолчанию 3%; это не гарантия будущей продажи.

Пауза чтений по умолчанию 0,100 с для V2 и не менее 0,103 с для V3 **после** RPC; диапазон настройки 0,1–0,5 с. Дополнительные проверки RPC увеличивают фактический интервал. При медленном узле gap-защита часто сбрасывает базу, о чём сообщает журнал. Скорость оригинала не обещается. Сохранённые ранее позиции сохраняют прежнюю базу TP/SL до закрытия.

Условия восстановлены статическим разбором машинного кода; полное совпадение программ не подтверждено. Доказательства, исправления и оставшиеся отличия: [актуальный аудит по ТЗ](docs/PARITY_AUDIT_RU.md).

## Converter, профили и Sweep

- Встроены 42 публичных адреса из EXE. Их присутствие в каталоге не подтверждает ликвидность или благонадёжность токена.
- V2/V3 маршруты проверяются по официальной factory, token0/token1, каноническому getPair/getPool и ненулевой ликвидности.
- **ADD BASE** добавляет сторону выбранного пула после котировки WBNB → base → WBNB на 0.001 WBNB; допустимая потеря обратной котировки до 15%, preview slippage 3%. Проверка не выявляет все ограничения продажи, налоги, blacklist или honeypot.
- **REMOVE** удаляет только пользовательский профиль и проверяет отсутствие остатков базы и известных target на указанном публичном кошельке.
- **BUY BASE** конвертирует заданное количество BNB в базу; **SELL ALL BASE → BNB** продаёт весь её баланс. Converter использует восстановленные preferred/fallback маршруты 42 встроенных профилей: прямые и через USDT, через ETH — для соответствующего профиля. Среди безопасных выбирается лучший котируемый выход, без оптимизации газа. Для динамических баз exact parity пока не подтверждено. Каждый кандидат проверяется обратной котировкой на фактическую сумму: допустимая потеря не более 15% (без газа и token tax).
- Путь конвертации исполняется одним V2 swap или V3 exactInput, с общим minOut. BUY передаёт BNB напрямую router. Approve и разворачивание WBNB после V3 SELL остаются отдельными транзакциями: при сбое unwrap полученный WBNB остаётся в кошельке, операция требует сверки. Deadline конвертера — 60 с; дополнительный tax buffer оригинала 5% не включён, minOut сохранён более строгим.
- **SELL WALLET → BNB** сначала продаёт target, зарегистрированные при выборе пула, затем базовые активы каталога и этих пулов. Нативный BNB не продаётся. Неизвестные ERC-20 не перечисляются автоматически.
- При отсутствии маршрута база пропускается с записью в журнал. Неоднозначная отправка, revert или ошибка после начала операции останавливает Sweep для сверки. Это строже поведения оригинала.
- После STOP или ошибки Sweep показывает частичный результат: обработанные активы, пропуски и непроверенные балансы. Если осталась незавершённая операция, журнал сообщает о необходимости сверки. Непроверенный баланс не считается нулевым.
- Балансы читаются последовательно; Multicall и зелёная сетка оригинала не воспроизведены. Ненулевые балансы выделяются зелёным в таблице.

## Хранение и восстановление

Без платного RPC на вкладке «RPC и кошелёк» уже выбраны публичный BNB Chain и PublicNode для резервных котировок. Нажмите «Подключить». В списках доступны альтернативный dataseed, собственные адреса и отключение резерва. Выбор адреса не запускает торговлю. При загрузке из Keychain собственный адрес сохраняется. Список не зависит от файлов Windows-релиза; это только BSC mainnet, HTTPS.

Актуальный список публикует [BNB Chain](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/). При проверке на этом Mac адреса bnbchain.org были недоступны, поэтому начальный адрес — проверенный публичный `https://bsc-dataseed.binance.org`; альтернативы Defibit/Ninicoin взяты из справочника chainId 56. Доступность и ограничения публичных узлов меняются; при подключении проверяются сеть/блок, перед LIVE — чтение receipts. PublicNode по умолчанию используется только для резервных котировок.

- Ключ и, по желанию, RPC: **macOS Keychain**, сервис `DipBotMac`, записи `wallet` и `rpc`. Нет fallback на открытый текст.
- Публичные маршруты, адрес кошелька, позиции и журнал: `~/Library/Application Support/DipBotMac/state.json`, права файла 0600. Ключи, RPC и лицензия туда не записываются.
- Перед отправкой на диск атомарно записывается hash подписанной транзакции. После потери ответа RPC повторная отправка автоматически не выполняется.
- При аварийном закрытии незавершённая операция блокирует LIVE. Подключите тот же кошелёк/RPC, нажмите **Проверить receipts**, обновите балансы. После ручной сверки можно снять блокировку.
- Снятие блокировки сбрасывает кэш позиций этого кошелька. Токены остаются на нём; используйте зарегистрированные маршруты и Sweep для выхода.
- Если receipt не найден, блокировка сохраняется. Для dropped/непереданной транзакции автоматической отмены или замены nonce в этой версии нет; необходим отдельный разбор hash и nonce. Не удаляйте журнал наугад.
- Успех требует `receipt.status == 1` и совпадения blockHash с каноническим блоком RPC. Баланс после swap/конвертации читается на блоке receipt. Ожидание дополнительной финальности и непрерывное восстановление после реорганизаций закрытых операций не реализованы. [Сверка блоков и настройка резервного RPC](docs/RPC_FAILOVER_RECEIPTS_RU.md).
- Приложение предотвращает запуск второго локального экземпляра. Не используйте тот же торговый кошелёк параллельно в другом боте: это нарушит учёт балансов и nonce.

### Сохранение параметров и дополнительный аудит

При штатном закрытии сохраняются проверенные AMOUNT/DIP/TP/SL/SLIPPAGE/DYNAMIC, GAS и интервал. Следующий запуск восстанавливает их в режиме DEMO. Некорректные сохранённые параметры заменяются значениями по умолчанию с сообщением в журнале. Также сохраняются router/pair и суммы отдельно для каждой пары. RPC и ключи не входят в эти настройки.

Sweep учитывает пулы сохранённых позиций кошелька, даже если запись отсутствует в каталоге. START/BUY другого пула блокируется при сохранённой позиции этого кошелька. Подробности нового статического разбора оригинала и ограничений: [отчёт](docs/STATIC_RECOVERY_AUDIT_RU.md).

### AutoPair и динамические маршруты

AutoPair выбирает наиболее ликвидный пул внутри одной router/пары. Несколько разных пар требуют ручного выбора. PENDING означает отсутствие ликвидности: повторите поиск позже. ADD BASE сохраняет проверенные параметры конвертера отдельно для V2/V3; старые CUSTOM-профили можно перепроверить через ADD BASE. [Реализованные правила и ограничения](docs/WORKFLOW_PARITY_RU.md).

AutoPair автоматически запускается через 220 мс после ввода полного адреса токена/пула. Поиск использует Multicall; изменение ввода отменяет применение прежнего результата. Sweep учитывает реестр TARGET выбранного кошелька, повторно ищет маршруты и сообщает остатки/ошибки чтения. Старые глобальные TARGET без привязки к кошельку могут потребовать повторного выбора перед Sweep.

При ответе RPC `already known` / `known transaction` бот ждёт receipt по ранее записанному локальному hash, без повторной отправки. Чужой hash или повреждённые поля receipt не снимают блокировку. Это не заменяет проверку финальности и фактических балансов.

## Новые инструменты проверки

- Необязательный WSS во вкладке RPC: подписка новых блоков, переподключение и HTTP fallback. URL сохраняется только в Keychain по галочке.
- Во время BUY/SELL отдельный read-only монитор продолжает обновлять цену в UI; новых параллельных сделок он не создаёт.
- Локальный архив рынка: до 10 MiB на запуск / 200 MiB на каталог, без автоматического удаления. Неполные записи не принимаются replay. Модель повторения и её ограничения описаны в [плане и результатах](docs/IMPROVEMENT_ROADMAP_RU.md).
- [USD-учёт](docs/USD_PNL_RU.md) сохраняет отметки курса при исполнении; новый закрытый результат не меняется вместе с текущим курсом. Старые сделки не пересчитаны.
