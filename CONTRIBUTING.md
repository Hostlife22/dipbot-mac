# Разработка DipBot Mac

Проект экспериментальный. Изменения торгового исполнения должны сохранять журналирование перед broadcast, проверку chainId, ограничение minOut и блокировку повторной отправки при неизвестном результате.

## Подготовка

```bash
git clone https://github.com/Hostlife22/dipbot-mac.git
cd dipbot-mac
uv sync --frozen --python 3.12 --group dev
git switch -c docs/your-change
```

Для разработки нужен macOS; LIVE-хранилище использует системный Keychain. Python 3.12–3.13 поддерживаются конфигурацией проекта. [Архитектура](docs/ARCHITECTURE_RU.md) описывает границы модулей.

## Правила изменений

- Документация — на русском; имена публичных UI-действий сохраняйте: START BOT, STOP, BUY/SELL, AutoPair.
- Python: отступы 4 пробела, явные имена, небольшие функции. Массовое переформатирование не смешивайте с исправлением поведения.
- Суммы токенов и minOut считайте целыми числами / Decimal. Float допустим для отрисовки, но не для raw amounts.
- Сетевые запросы и ожидание receipt выполняются в Worker, не в UI-потоке.
- Входные данные не должны обходить проверку канонического пула и chainId 56.
- При изменении зависимостей обновляйте `pyproject.toml` и `uv.lock` вместе. Не обновляйте зависимости попутно с документацией.
- Новые функции проверяйте тестами поведения. Для документационных изменений достаточно проверки ссылок, команд и diff.

## Проверка

```bash
uv run --frozen pytest -q
QT_QPA_PLATFORM=offscreen uv run --frozen python launcher.py --smoke-test
git diff --check
```

При изменении упаковки дополнительно:

```bash
./BUILD_MAC.command
QT_QPA_PLATFORM=offscreen "dist/DipBot Mac.app/Contents/MacOS/DipBot Mac" --smoke-test
codesign --verify --deep --strict "dist/DipBot Mac.app"
```

Тесты подменяют HTTP-запросы через requests и используют локальные заглушки вместо отправки транзакций. Новые тесты также должны работать без кошелька и реальной сети. Read-only RPC-проверки запускаются отдельно и отмечаются в отчёте.

Реальные транзакционные проверки требуют явного разрешения и отдельного тестового кошелька. Нельзя превращать их в автоматический шаг CI.

## Коммиты и pull requests

Используйте короткие названия, например `docs: clarify recovery flow`, `fix: preserve minOut after approval`, `ci: test macOS builds`.

В PR опишите проблему, итоговое поведение и проверки. Для интерфейса приложите скриншот DEMO без данных кошелька. Отдельно укажите непроверенные сценарии. Пользовательские изменения отражайте в `CHANGELOG.md`, историю исходного аудита не переписывайте как результат новой проверки.

Не добавляйте в Git `.nrnflic`, private key, seed-фразы, RPC с токенами доступа, `state.json`, файлы кошельков или исходный Windows-дистрибутив. `.gitignore` — вспомогательная защита; перед коммитом просматривайте staged diff.

## CI и сборки

- `ci.yml`: pytest и GUI smoke test на push / pull request, macOS Intel + Python 3.12 и Apple Silicon + Python 3.13.
- `build-macos.yml`: ручная сборка `.app` на обеих архитектурах, проверка запуска и подписи, ZIP и SHA-256 как Actions artifacts.
- Actions закреплены по commit SHA; Dependabot предлагает обновления ссылок. Сборка не публикует релиз и не подписывается Developer ID.


## Документация и артефакты

Начните с [индекса](docs/README.md). Обновляйте существующие руководства вместо создания очередного датированного отчёта. Сохраняйте результаты прогонов и скриншоты в `.local-artifacts/` или `/tmp`; необходимые fixtures тестов остаются в Git. Исторические анализаторы и отчёты доступны на `89e3a4f`.

## Архитектура

Новые модули размещайте по ответственности согласно [архитектуре](docs/ARCHITECTURE_RU.md). `tests/test_architecture.py` запрещает зависимости domain от фреймворков и приложения от tools/tests. CI также проверяет запуск установленного wheel с недоступными tools/tests. Не переносите бизнес-логику в построение Qt-экранов и не создавайте второй поток отправки транзакций.
